## 2. Архитектурные решения

**[I5-1] Одна точка входа для JS.** `js/pwa.js` подключается `import` из `app.js`, а не вторым `<script>`: в проекте один способ загрузки кода — ES-модули от `app.js`. `pwa.js` — инфраструктура уровня `data.js`: не экран и не чистая логика (`PRODUCT.md` 10.3), в роутинг и `#view` не вмешивается.

**[I5-2] Префикс кэша `sanya-guide-`.** У всех репозиториев на `<аккаунт>.github.io` общий origin и общее хранилище Cache API. `activate` удаляет только ключи с этим префиксом, кроме текущего — чужие кэши на том же origin не трогаются (проверено: `other-app-v1` пережил обновление).

**[I5-3] `cache: "reload"` при precache.** GitHub Pages отдаёт файлы с `max-age=600` (F-16). Без обхода HTTP-кэша новая версия воркера могла бы положить в новый кэш старые файлы из HTTP-кэша браузера.

**[I5-4] `clients.claim()` в `activate`.** Страница первого визита сразу переходит под контроль воркера: если сеть пропадёт в этой же сессии, экраны, чьи JSON ещё не загружались, получат их из кэша. `skipWaiting()` при этом не вызывается — первая установка активируется сама (ждать нечего), обновление ждёт подтверждения.

**[I5-5] Когда перезагружаться по `controllerchange`.** Если при загрузке страницы контроллера не было, первый `controllerchange` — это `clients.claim()` первой установки: перезагрузки нет. Если контроллер был, его смена возможна только после `SKIP_WAITING`, то есть после «Обновить» — здесь или в другой вкладке; тогда `location.reload()`. Автоматического обновления без подтверждения нет.

**[I5-6] Cache-first без runtime-кэширования.** Свои GET-запросы: сначала кэш текущей версии (`caches.open(CACHE_NAME)`, а не общий `caches.match` — во время ожидания обновления старый воркер не отдаёт файлы нового кэша), иначе сеть; ответы сети в кэш не кладутся. Внешние запросы и не-GET не перехватываются. `ignoreVary: true` — чтобы заголовок `Vary` хостинга не ломал совпадение.

**[I5-7] Навигация → `index.html`.** Любой `mode === "navigate"` в области действия отдаётся как закэшированный `index.html` (hash-роутинг, D-24): `./`, `./index.html`, `./?utm=…` открывают приложение офлайн. `start_url: "."` → `/<репозиторий>/` → `index.html` → `#/`.

**[I5-8] Отличие офлайна от прочих ошибок — в `data.js`.** `fetch()` отклоняется только при сетевой ошибке; тогда ошибка получает `offline = true`. `loadErrorMessage(e)` выбирает текст; разметка `renderErrorState` в экранах, Promise-кэш и «Повторить» не менялись. 404 и повреждённый JSON показывают прежнее «Не удалось загрузить данные».

**[I5-9] Плашки — вне `#view`.** Контейнер `.pwa-bars` добавляется в `body` после `#app`: ре-рендер экранов его не стирает, он не участвует в истории. Стоит над нижней панелью; его высоту `ResizeObserver` пишет в `--pwa-bars-height`, а новые правила CSS прибавляют её к нижнему отступу `.app-main` и к `bottom` у `.place-actions` — конец экрана и закреплённые действия карточки не прячутся под плашкой. На полноэкранных экранах (`#app.is-fullscreen ~ .pwa-bars`) плашек нет: там нет нижней панели, а внизу — «Скопировать» / «Закрыть».

**[I5-10] Подсказка только в secure context.** На `http://192.168.x.x` офлайн физически недоступен, и обещание «будет работать без интернета» было бы ложным — подсказки там нет, как и регистрации.

**[I5-11] Версия — из воркера.** Строка «Версия …» получает `CACHE_VERSION` у активного воркера через `MessageChannel` (`GET_VERSION`) — второй константы версии нет. Без воркера (LAN, приватный режим) показывается только «Данные обновлены: …». Дата — самая поздняя `verifiedAt` среди показываемых данных (`info`, `checklist`, verified `places`, `contacts`, `phrases`), без выдуманной «даты релиза».

**[I5-12] «← Назад» в `#/settings`.** Тот же `leave()`, что у «Готово», но без сохранения: `ctx.back(ctx.from || "#/")` или `replace("#/")` после первого запуска. В режиме первого запуска кнопки нет: родителя у экрана нет, выход без сохранения там — «Пропустить всё» ([I3-1]). Остальные вложенные экраны уже имели видимый возврат: «← К местам» (вверху карточки), «Закрыть» (полноэкранные), «← Назад» («Под рукой»), «← К справке» (внизу карточки справки — не переносилась, M8 требует добавлять только отсутствующие).

**[I5-13] Шапка и safe area.** Новое правило `padding-top: calc(16px + env(safe-area-inset-top))` у `.app-header`: в установленном приложении с `viewport-fit=cover` шапка не уходит под системную строку. В браузере inset = 0, вид не меняется.

**[I5-14] `apple-mobile-web-app-capable` вместе с `mobile-web-app-capable`.** Первый — страховка standalone-режима на iOS, второй убирает предупреждение Chrome об устаревшем мета-теге.

## 6. Update flow

1. Владелец меняет `CACHE_VERSION`, публикует.
2. Пользователь открывает приложение с сетью. Браузер проверяет `sw.js` при навигации (`updateViaCache: "none"` — мимо HTTP-кэша); установленное приложение, вернувшееся из фона, дополнительно проверяет `registration.update()` по `visibilitychange`.
3. Новый воркер скачивает precache в `sanya-guide-<новая>` и остаётся `waiting`. Приложение продолжает работать на старой версии и старом кэше.
4. Появляется плашка «Доступна новая версия · Обновить» (первой, над подсказкой установки, если та тоже видна).
5. «Обновить» → `postMessage({ type: "SKIP_WAITING" })` → воркер активируется, `activate` удаляет прежние кэши `sanya-guide-*` и делает `clients.claim()` → `controllerchange` → `location.reload()`.
6. После перезагрузки — новые файлы и данные, в «Справке» новая версия. hash текущего экрана сохраняется; стек истории внутри сессии — как у обычной перезагрузки.
7. `stg:checklist`, `stg:saved`, `stg:trip`, `stg:schema` не затрагиваются: обновление меняет только Cache API.

Если `controllerchange` не пришёл, через 4 с кнопку можно нажать снова; плашка не исчезает, приложение работает на прежней версии.

## 7. Offline flow

| Ситуация | Поведение |
|---|---|
| Приложение хоть раз открыто с сетью в secure context | Всё из кэша: холодный старт, перезагрузка, все маршруты и `start_url`; ни одного запроса в сеть не требуется |
| Первое открытие без сети, кэша нет | Документ не загрузится — это браузерная страница ошибки, приложение на неё не влияет |
| Документ загружен, но нужного JSON нет ни в кэше, ни в сети (воркер не установлен, кэш удалён системой, первая сессия до установки) | «Нет соединения. Откройте приложение один раз с интернетом, чтобы оно снова заработало офлайн.» + «Повторить»; у полноэкранной фразы и экрана таксиста — ещё «Закрыть». Сеть вернулась — «Повторить» загружает экран (Promise-кэш после ошибки очищается, как раньше) |
| `http://192.168.x.x` | Как до Итерации 5: только текущая сессия страницы |

## 8. Известные ограничения

1. **Реальные устройства не проверялись.** iOS Safari standalone, авиарежим после перезагрузки телефона, возврат в приложение после звонка `tel:`, Chrome Android, Яндекс Браузер — только после публикации (`ITERATION-5-CLOSEOUT.md`). Headless Chrome эмулирует standalone (`navigator.standalone`), iPhone (UA) и отсутствие сети (остановка сервера), но это не iOS WebKit.
2. **Первое открытие должно быть с сетью** и по HTTPS. На `http://192.168.x.x` офлайна нет (F-13) — проверка на телефоне только по опубликованной ссылке.
3. **Без установки на экран iOS может удалить кэш и `localStorage`** через 7 дней без взаимодействия (F-14). Меры — подсказка, пункт чек-листа; экспорт/импорт не делались.
4. **Новый файл приложения нужно вписать в `PRECACHE` вручную** (сборки нет, D-23). Автотест сверки ловит расхождение, но запускается в песочнице сеанса, не в репозитории.
5. **Забытая смена `CACHE_VERSION`** = пользователи остаются на старой версии (R5-1). Смягчение — README; автоматизации нет.
6. **Разработка на `127.0.0.1` / `localhost`**: воркер отдаёт файлы из кэша, правки не видны после обычной перезагрузки — в README описан «Bypass for network».
7. **После обновления** стек истории — как после перезагрузки страницы (сценарий 4 §7 исследования).
8. **Публикуется весь репозиторий**, включая `*.md` и `tools/`. В приложение и кэш они не попадают.

### 10.5 Чего автоматическая validation не покрывает

- Chrome Android, Яндекс Браузер (D-31), настоящий системный диалог установки.
- GitHub Pages как хостинг (HTTPS, `max-age=600`, редирект `/<репозиторий>` → `/<репозиторий>/`) — стенд эмулирует только подпапку.
- Доступность из Китая (Q-04).
