## 4. Storage

| Ключ | Значение |
|---|---|
| `stg:myplan` | `{ planId, days: { "ГГГГ-ММ-ДД": { type?, title?, summary?, morning?, afternoon?, evening?, placeIds?, tips?, alt?, origin } } }` |

- **[I6-3] Полная копия, не diff.** День «Моего плана» — копия дня рекомендации (без `date`) с `origin: "recommended"` или день пользователя с `origin: "user"`. Минимальный валидный день — `{ "placeIds": ["luhuitou-park"], "origin": "user" }`.
- **Белый список при записи и чтении:** известные текстовые поля — только непустые строки; `placeIds` — строки без повторов, не больше 3; `tips` — строки; неверный ключ даты (`2026-02-31`, `bad`) и день без содержимого отбрасываются; неизвестный `origin` → `"user"`.
- **Терпимое чтение:** нет ключа → `{ planId: null, days: {} }`, ключ не создаётся; битый JSON / массив / строка / число → пустой план, **одна** `console.error`, сырое значение не перезаписывается (прецедент `stay`, `home`). Перезапись — только действием пользователя.
- **`stg:schema` = 1**, миграций нет, других новых ключей нет.
- **Хранилище недоступно:** экраны открываются, операции показывают «Не удалось сохранить: хранилище браузера недоступно.» без исключений.
- **Обновление рекомендации** не меняет `stg:myplan` ни на байт (проверено подменой `plan.json` и `CACHE_VERSION`, 11.3 M2).

## 6. S1: добавление места, начиная со дня

```
#/plan/D ──«Добавить место»──▶ #/places?addTo=D ──строка──▶ #/place/<id>?addTo=D ──«Добавить на D»──▶ history.go(-2) ▶ #/plan/D
```

- **`addTo` живёт в URL.** `placesHash(tokens, near, addTo)` — переключение чипов, снятие чипов и «Показать все» пишут `addTo` обратно через `replaceState`; строки списка ведут на `#/place/<id>?addTo=D`; сортировка и радиус — прежние.
- **[I6-5] Back без лишних записей.** Список выбора открывается только поверх самого дня: если `ctx.from` списка — не `#/plan/D` (глубокая ссылка, открытие в новой вкладке), выполняется `location.replace("#/plan/D")`. Записи истории хранят `from` и после перезагрузки, и после возврата, поэтому инвариант «перед списком выбора лежит день D» выполняется всегда. Карточка с `addTo` работает в режиме выбора только при `ctx.from = #/places?addTo=D`; иначе параметр снимается `replace`. Поэтому после успешного добавления `history.go(-2)` гарантированно возвращает в день D: пользователь видит результат, а системный «Назад» из дня ведёт туда, откуда пришли в день, а не на экран выбора.
- До завершения действия системный Back работает как обычно: карточка → список (с фильтрами и `addTo`) → день. «Отмена» на плашке списка — `ctx.back("#/plan/D")`; «← К местам» на карточке — `ctx.back("#/places?addTo=D")`.
- Для занятого дня на карточке — инлайн «Добавить к текущему плану» / «Заменить текущий план» / «Отмена»; место уже в дне — «Добавить на 24 ноября: уже в плане.»; в дне 3 места — «…: в дне уже 3 места.».
- Draft-места в список не попадают (`loadPlaces()` отдаёт только verified), `#/place/<draft>` и `#/place/<draft>/plan` → `#/places`.

## 7. Операции (`js/logic/myplan.js`)

| Операция | Результат | Особый случай |
|---|---|---|
| `acceptDay(myPlan, recDay)` | Копия дня на его дате, `origin: recommended` | Повтор — та же дата, дубликата нет; занятую дату экран сначала подтверждает |
| `acceptAll(myPlan, plan)` | 14 дней, `planId = meta.id`, `days` перезаписан целиком | Непустой план — экран спрашивает «Заменить весь план рекомендованным?» |
| `clearDay(myPlan, date)` | Ключ удалён | — |
| `moveDay(myPlan, from, to)` | `to` = содержимое `from`, `from` пуст, `origin: user` | Цель занята — «Заменить содержимое» (эта же операция) или «Поменять местами» |
| `swapDays(myPlan, a, b)` | Обмен, `origin: user` у обоих | С пустой датой = перенос |
| `addPlace(myPlan, date, placeId)` | +1 место, остальное содержимое сохраняется, `origin: user`; день создаётся при отсутствии | Повтор и 4-е место — план не меняется (`getAddPlaceStatus`: `duplicate` / `full`) |
| `replaceDayWithPlace(myPlan, date, placeId)` | `{ placeIds: [placeId], origin: user }` | — |

Все операции возвращают новый объект, массивы копируются; вход и объект рекомендации не мутируются (проверено заморозкой снимка). `js/logic/` не обращается к DOM, хранилищу и адресу страницы.

**Отрисовка дня (`renderDayBody`) — одна на оба слоя.** Заголовок: `title` → названия мест через запятую → «Пока ничего не запланировано». Чип — только при `type` из справочника. «Утро / День / Вечер», «Места этого дня», «Советы», «Если не хочется» — только при наличии полей; прочерков и пустых заголовков нет.

## 12. Известные ограничения

1. **Устройства.** Ручной QA на реальном iPhone пройден владельцем 2026-09-13. Chrome Android и Яндекс Браузер не проверялись.
2. **Смена суток при открытом приложении** (полночь, Москва ↔ Санья): «сегодня» пересчитывается при каждом рендере экрана, но открытый экран сам не перерисовывается (R6-13). «Сегодня» — локальная дата устройства, как у состояний Главной с Итерации 3.
3. **После `history.go(-2)` в S1 запись «вперёд»** ведёт на список выбора и карточку. Системный «Вперёд» на телефоне практически недоступен; экраны при этом корректны.
4. **Прямая ссылка на `#/places?addTo=<date>` или `#/place/<id>?addTo=<date>`** (новая вкладка, ручной ввод) не открывает режим выбора: список уходит на день, карточка — в обычный режим. Это цена гарантии Back из раздела 6. Из приложения, после перезагрузки и из установленного приложения (`start_url = .`) режим работает.
5. **Возврат «← К моему плану» после переноса / добавления через `replace`** выполняется `replace` на `#/plan` (запись дня создана `replace`-ом, `from` у неё — экран выбора). Системный «Назад» при этом ведёт на исходный день / карточку, как требует research §9.9.
6. **Текст принятого дня не обновляется** вслед за рекомендацией (осознанное свойство полной копии, §6.2); уведомления нет (S3 отложен). Чтобы получить новую версию, пользователь берёт день заново; отметка «✓ в моём плане» у изменившегося дня пропадает, и кнопка «В мой план» снова доступна (проверено).
7. **Дни вне периода** (если период рекомендации когда-нибудь изменится) остаются в `stg:myplan`, но не показываются, пока доступен `plan.json` (§12.5).
8. **Дата «сегодня» в сценариях Главной** проверена подменой `Date` в headless Chrome, а не реальным ожиданием ноября.
9. **Подсказка установки на 320×568** (Итерация 5, §8 п. 11) по-прежнему занимает низ экрана; кнопки плана доступны после прокрутки, не перекрыты (проверено группой N с видимой плашкой).
10. **Контент рекомендации — план одного владельца под одни даты** (R6-14): подзаголовок честно называет район и период.
