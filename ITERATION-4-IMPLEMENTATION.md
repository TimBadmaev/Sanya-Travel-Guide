## 2. «Под рукой» (`#/handy`)

### 2.1 Маршруты

| Маршрут | Экран | `nav` | `fullscreen` |
|---|---|---|---|
| `#/handy` | Адрес, контакты, фразы | `/info` | — |
| `#/handy/phrase/<id>` | Фраза на весь экран | `/info` | да |
| `#/handy/taxi` | Адрес проживания для таксиста | `/info` | да |

**[I4-1] Подсветка «Справка».** Прецедент — ссылки Главной «Такси и Amap» и «Экстренные номера» ведут в карточки справки и подсвечивают «Справку». «Под рукой» открывается из двух мест (Главная в поездке и список «Справки»), и отдельной вкладки у него нет (D-07 — 4 вкладки).

**[I4-2] «← Назад».** Родитель — `ctx.from`, если это `#/` или `#/info`; иначе (глубокая ссылка, перезагрузка, приход с экрана фразы после replace) — `#/info`. Выход — `ctx.back(parent)`: с родителя `history.back()` (прокрутка и состояние родителя сохраняются), иначе replace. Прямая проверка `ctx.from` понадобилась потому, что после `location.replace` в `from` может оказаться hash заменённой записи — `history.back()` на него увёл бы из приложения.

Контракт роутера (`ctx.params/query/from/isCurrent/back`), `navId`, привязка прокрутки к записи истории — не менялись.

### 2.2 Состав экрана

1. **«Адрес проживания»** — адрес (`lang="zh-CN"`) и название, кнопка «Показать таксисту» → `#/handy/taxi`, ссылка «Изменить адрес» → `#/settings`. Без адреса — пустое состояние «Адрес не указан. Добавьте адрес отеля на китайском в настройках поездки — его можно будет показать таксисту.» и кнопка «Указать адрес» → `#/settings`.
2. **Контакты по группам** в порядке `CONTENT-ITERATION-4.md` §2: «Экстренные службы», «Такси», «Город», «Цены и качество», «Консульство России». Внутри группы — порядок файла. Подписи групп — деталь отображения в `handy.js` (как `ICONS` в `info.js`); неизвестная группа попадёт в конец под «Другое».
3. **«Фразы на китайском»** — 16 строк: русский, китайский (`lang="zh-CN"`), контекст; тап → фраза на весь экран.
4. Подвалы разделов контактов и фраз — «Проверено: <месяц год>» (самая поздняя `verifiedAt`) и источники без повторов.

**[I4-3] Номер не дублируется текстом.** Строка контакта — одна ссылка `<a href="tel:…">` целиком: подпись, номер, пояснение внутри неё, `aria-label="Позвонить: Полиция, 110"`. Отдельной строки с номером рядом с кнопкой нет — автотест проверяет, что номера не встречаются в `#/handy` вне ссылок `tel:`.

**[I4-4] Карточка справки «Экстренные номера» не менялась.** Раздел 5 `CONTENT-ITERATION-4.md` правит только пункты 5.1 и 5.2; тексты карточек без прямого требования не меняются. Номера в этой карточке остаются текстом для чтения — вопрос владельцу (раздел 12, №6).

### 2.3 Фраза на весь экран

Строки сверху вниз: иероглифы (`.taxi__name`, 32px, `lang="zh-CN"`), пиньинь (`.taxi__pinyin`, 22px), перевод (`.taxi__ru`). «Скопировать» копирует китайский текст. «Закрыть» — `ctx.back("#/handy")`. Неизвестный `id` → `location.replace("#/handy")`.

### 2.4 Один полноэкранный механизм [I4-5]

Задание запрещает второй похожий механизм. Разметка «Показать таксисту» (`.taxi`, `.taxi__content`, `.taxi__actions` [«Скопировать», «Закрыть»], `.taxi__status`), `copyText()` с запасным путём через `execCommand` и `bindCopyButton()` перенесены из `place.js` в `js/views/taxi.js` без изменений поведения (прецедент — `task.js`, вынесенный в Итерации 3). `renderShowScreen(container, { lines, getCopyText, closeHref, onClose })` используют три экрана: место, адрес проживания, фраза. Скрытие шапки и панели — прежний флаг маршрута `fullscreen` в роутере.

DOM экрана таксиста у места не изменился: те же классы, тексты и порядок кнопок (проверено тестами Итерации 2–3 и группой F Итерации 4).

## 3. Адрес проживания (Q-15)

### 3.1 Модель

```json
{ "start": "2026-11-12", "end": "2026-11-27", "area": "yalong",
  "stay": { "source": "spot", "spotId": "yalong-beach-front" },
  "home": { "addressZh": "海南省三亚市…酒店", "nameRu": "Отель у пляжа" } }
```

| Поле `home` | Правило |
|---|---|
| `addressZh` | Обязательна непустая строка после `trim()`; пустая → `home: null` без сообщения об ошибке (так форма сохраняет очищенное поле) |
| `nameRu` | Необязательна; пустая после `trim()` не сохраняется |
| прочие поля | Отбрасываются белым списком `normalizeHome()` |

**[I4-6] Решения по модели.**
- `home` — **не точка отсчёта**: координаты у адреса нет, `resolveOrigin()`, `trip.area` и `trip.stay` не менялись. Расстояния считаются как в Итерации 3.
- `note` из примера Q-15 не реализован: в минимальном пакете ему нет применения, поле «на будущее» противоречит `CLAUDE.md`.
- Приложение адрес не проверяет и не требует иероглифов — показывает так, как ввёл пользователь (подсказка на экране это говорит).
- `stg:schema` остаётся `1`, миграций нет: значение Итераций 1–3 без `home` читается как `home: null`.
- Повреждённый `home` (не объект) → «адреса нет» + один `console.error`, сырое значение не перезаписывается — тот же принцип, что у `stay` ([I3-4]).
- `setTrip()` по-прежнему белый список: вызывающая сторона передаёт `home` целиком. Единственный вызов — `settings.js`.

### 3.2 Ввод в `#/settings`

- Блок «Адрес для таксиста» — **только в обычном режиме**. Первый запуск остаётся двумя блоками (MVP-UX-SPEC §8); при сохранении в режиме первого запуска передаётся уже сохранённое `trip.home` («Пропустить всё» — `home: null`, ключа до этого не было).
- Поля: `textarea` «Адрес на китайском» (2 строки) и `input` «Название по-русски (необязательно)»; подписи над полями; `maxlength=200`; шрифт 16px (iOS не зумит).
- Смена района сбрасывает `stay`, но **не** `home`: адрес не принадлежит району.
- Выход после «Готово» — прежний `ctx.back(ctx.from || "#/")`: из «Под рукой» возвращает в «Под рукой» с новым адресом.
- Текст вступления: «Даты, район и адрес можно изменить в любой момент.»

### 3.3 «Показать таксисту» для адреса

`#/handy/taxi` → `renderShowScreen`: адрес крупно (`.taxi__name`, `lang="zh-CN"`), под ним `nameRu` или «Адрес проживания». «Скопировать» — только адрес. Экран не грузит JSON (данные из `localStorage`). Без адреса глубокая ссылка → `location.replace("#/handy")` (пустое состояние).

### 7.3 Как устроено

- **Логика** (`js/logic/filters.js`): `export const NEAR_RADIUS_KM = 20;` и `filterWithinRadius(places, center, radiusKm = NEAR_RADIUS_KM)` — чистая функция, новый массив, порядок входа сохраняется, сравнение нестрогое (`<=`), `center == null` → копия без ограничения, место без координат (NaN) не проходит.
- **Главная** (`home.js`): в состоянии «В поездке» при `precision !== "none"` все 4 сценария получают `near=1`: `#/places?near=1`, `#/places?f=short&near=1`, `#/places?f=nature&near=1`, `#/places?f=indoor&near=1`. Без точки отсчёта ссылки прежние («Рядом с отелем» → `#/settings`). Сценарии «Без дат / После поездки» («Хочу на пляж» и др.) — это выбор до поездки, радиус к ним не применяется.
- **«Места»** (`places.js`): `near=1` учитывается только при известной точке отсчёта (иначе молча игнорируется). Порядок — радиус → фильтры → `sortByDistance` (сортировка сохранена). Над результатами — плашка «Показаны места в радиусе 20 км от места проживания / от центра района. **Показать все**»; число — из константы. «Показать все» снимает радиус через `replaceState` без навигации (как снятие чипа), фокус переводится на первый чип. Переключение чипов сохраняет `near=1` в URL. Если в радиусе пусто и фильтров нет — пустое состояние «В радиусе 20 км мест не найдено.» с кнопкой «Показать все». Подсказка «Снять «…»» считает по местам в радиусе. «Вы пока ничего не сохранили» — по всем местам (сохранённое вне радиуса не делает избранное «пустым»).
- **[I4-9] Почему URL-параметр, а не чип.** Задание запрещает новый сложный UX; отдельный чип «Рядом» уже был отклонён (MVP-UX-SPEC §4, решение №1). Параметр живёт в URL, как и фильтры: Back/Forward и перезагрузка дают тот же список.
