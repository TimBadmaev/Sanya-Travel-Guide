## 1. Current state (что приложение умеет на самом деле)

**Навигация.** 5 вкладок: Сейчас · Места · Экскурсии · Подготовка · Справка. Hash-роутинг
таблицей regexp (`js/app.js`), 25 маршрутов (после итерации — 27), у каждого вложенного экрана своя кнопка возврата,
`ctx.back()` не растит историю.

**Сейчас (`#/`).** Четыре состояния по датам `stg:trip`: без дат / до поездки / в поездке / после.
В поездке сверху были 4 кнопки сценариев поиска («Рядом с отелем», «Есть 2–3 часа», «Хочу
природу», «В помещении»), под ними одна карточка-ссылка «Сегодня по плану: <заголовок>», затем
«Расходы сегодня» + «+ Расход», «Если планы меняются», «Поесть рядом», «Под рукой».

**План.** Рекомендация `data/plan.json` (13–26 ноября 2026, 14 дней) только читается; «Мой план»
— полная копия в `stg:myplan`. День: тип, summary, ритм **morning / afternoon / evening** (текст, не
время), до 3 пунктов (места + экскурсии), советы, `alt`. Операции: взять день/весь план, добавить
место или экскурсию, «Заменить текущий план», перенести/поменять местами, очистить. «✓ в моём
плане» у рекомендации — `isSameAsRecommended()`.

**Места / экскурсии / еда.** 52 verified места, 36 экскурсий, 19 точек еды. Поиск RU/EN/ZH +
категория/синонимы/теги/район/описание. Фильтры в URL. «Рядом со мной» по геолокации.
Карточка: «Показать таксисту» (китайский адрес крупно), «Как добраться» (Amap), избранное,
«Добавить в мой план».

**Расходы (Iteration 8).** `stg:expenses` (исходная сумма и валюта, 4 валюты, 10 категорий,
необязательная ссылка на пункт плана `link: {kind, id}`), `stg:budget` (курс поездки, бюджет).
Итоги сегодня / поездка / категории / дни, бюджет с перерасходом, «Скопировать отчёт» текстом.

**Офлайн.** Service Worker cache-first, явный PRECACHE, `v14`, обновление по кнопке «Обновить».

**Хранилище пользователя:** `stg:trip`, `stg:checklist`, `stg:saved`, `stg:myplan`,
`stg:expenses`, `stg:budget` (+ служебные `stg:schema`, `stg:installHintDismissed`,
`stg:expenses:backup`). Всё — только в `localStorage` этого браузера.

### Что выяснилось при аудите кода (расходится с ожиданиями задания)

| Ожидание | Факт в коде | Вывод |
|---|---|---|
| «Существующие отметки выполнения плана» | Отметок «сделано» у пунктов плана **нет**. «Отметки» в коде — это чек-лист подготовки (`stg:checklist`) и признак «✓ в моём плане» | «Выполнено» — новый слой состояния, а не доработка |
| У плана есть «текущая / следующая активность» | Времени у пунктов нет, есть только текстовый ритм «утро / день / вечер» | «Сейчас / дальше» = часть дня по часам телефона + первый не отмеченный пункт |
| Даты поездки — одна сущность | **Две:** `stg:trip.start/end` (ввёл пользователь, управляет «День N из M») и `plan.json → meta.startDate/endDate` (период рекомендации, управляет блоком плана) | «Сегодня» показывается, только когда сегодняшняя дата внутри периода плана **и** в «Моём плане» есть этот день; иначе — прежняя логика, без ложного «сегодня поездки» |
| `hours` можно считать | Непустой `hours` у 38 из 52 verified мест (у HTDF и аутлета — пустая строка), всё — свободный текст (сезоны, «по независимому источнику», «уточняйте») | Нужна отдельная структура рядом с текстом, не парсинг текста |
| Контент чистый | У 5 магазинов в **«Советах»** (видны туристу) лежали служебные заметки проверки: «GCJ-02 → WGS-84 (D-19)», «Район отнесён… config.areas», «Черновик снят…» | Реальный дефект контента, исправлен (§9 implementation) |
| `hours` HTDF | Пустая строка `""` | Найдены официальные часы оператора — заполнено |

## 2. What became possible after Iteration 8

- Расход уже умеет ссылаться на пункт дня (`link`) → «расходы дня по пунктам плана» не требуют
  новой модели, только показа.
- «Если планы меняются» уже ведёт в существующий режим выбора места для дня
  (`#/places?addTo=<дата>` → «Заменить текущий план») → замену дня не нужно изобретать заново,
  её достаточно сделать ближе (ссылка «что открыто сейчас» с экрана дня).
- Расходы сделали `localStorage` местом, где лежат **невосстановимые** данные. До Iteration 8
  потеря хранилища стоила пары минут (даты, избранное), теперь — всех трат поездки. Это
  превращает экспорт/импорт из «удобства» в **safety-функцию**.
- Поиск по смыслу закрыл discovery; значит, главному экрану больше не нужно начинаться с
  кнопок поиска.

## 3. Current UX bottlenecks (где продукт ещё справочник)

1. **Первый экран в поездке отвечает на «что найти?», а не на «что делать?».** Сверху — четыре
   кнопки поиска; то, что запланировано на сегодня, — одна строка-ссылка под ними. Чтобы понять
   «что сейчас и что дальше», нужно открыть день.
2. **Нет понятия «сделано».** План нельзя «проживать»: нечем отметить, что остров уже был, и
   нечем показать «следующее».
3. **Нет «открыто ли сейчас».** Часы — только текст в карточке. Вечером турист открывает
   несколько карточек подряд, чтобы понять, куда ещё можно успеть.
4. **Данные можно потерять одним действием ОС.** Единственная «копия» — текстовый отчёт о
   расходах: план, избранное, курс и отметки он не восстанавливает, и восстановить из него
   ничего нельзя.
5. **Расходы дня отделены от пунктов дня.** Привязка к пункту есть в данных, но на экране дня
   видна только общая сумма.
6. **Последний день ничем не отличается** от остальных, хотя в «Справке» уже есть проверенные
   карточки про доставку багажа, получение duty free и возврат НДС в аэропорту.

## 4. Решение по вкладкам (обязательный вывод)

**Оставить 5 вкладок (вариант A). В этом запуске навигацию не менять.**

Аргументы:
- «Экскурсии» — не вариант «Мест», а другой ответ: *куда поехать на полдня/день* (36 сценариев
  выезда с маршрутом из нескольких мест, форматом, нагрузкой). Места — *что это за объект*.
  Слияние в «Места» сделало бы переключатель уже третьим режимом вкладки (места / еда /
  экскурсии) с разными фильтрами — это дороже для пользователя, чем пятая иконка.
- В поездке главные входы в экскурсии теперь идут не через вкладку, а через ситуации: «Дождь»,
  «Вечер», «Что делать сейчас», «Если планы меняются» — частота использования самой вкладки не
  критична для сценария дня.
- 5 вкладок уже проверены на 320 px (подписи 11 px до 359 px, «Подготовка» не обрезается).
- Изменение навигации ломает десятки URL/подсветок/возвратов (8.1 PRODUCT.md) — риск больше
  пользы в итерации, чья цель — сценарий дня.

**Когда вернуться к вопросу:** если «Подготовка» после вылета перестанет быть нужна —
кандидат на объединение со «Справкой» (P2), а не «Экскурсии».

## 5. P0 — делать сейчас

1. **«Сегодня» на первом экране.** Карточка: заголовок дня, «Сейчас, днём: …» / «Дальше,
   вечером: …» по часам телефона, пункты дня с кнопкой «сделано» и меткой «Следующее»,
   «Завтра: …»; заголовок карточки ведёт в день. Выше кнопок поиска. Источник — `stg:myplan`, без копии.
2. **Экспорт / импорт всех данных пользователя** одним версионированным JSON: файл, «Отправить…»
   (Web Share), текст в буфер; импорт из файла или вставленного текста; предпросмотр,
   подтверждение, снимок прежних данных и «Вернуть как было». Офлайн.
3. **Структурированные часы для 15 ключевых мест** + движок «открыто сейчас» (обычный график,
   выходной день недели, перерыв, работа через полночь, сезоны, временное закрытие, неизвестно).
4. **«Что делать сейчас»** (`#/now`): прозрачные правила — открыто по подтверждённым часам, хватает
   минимального времени до закрытия, ближе к жилью выше; фильтры «В помещении» / «Легко» /
   «До 2 ч»; места без часов — отдельно, «Часы не подтверждены».
5. **Мобильная/офлайн-проверка** на 320/360/390/430, апгрейд v14 → v15, офлайн-импорт.

## 7. P2 — не делать (и почему)

- **Плановая стоимость и «план vs факт».** Числа в контенте — цена *билета на человека* в тексте
  `price.note` (лесной парк 158 ¥ с 1 октября, Наньшань 129 ¥, остров «от 136 ¥»). Нет числа
  людей в поездке, нет транспорта и еды, у 28 из 52 verified мест `price.type = unknown`. «План ~¥350»
  был бы выдуманной точностью. Честный максимум сейчас — цена билета в карточке, она уже есть.
- **Время в пути.** В данных его нет, решение X-12/D-11 — не показывать. «Что делать сейчас»
  говорит об этом прямо.
- **Индикатор «готово для офлайна».** После экспорта/импорта главный риск офлайна — потеря
  данных — закрыт; сам офлайн уже работает (PWA, обновление по кнопке). Индикатор не дал бы
  новой возможности.
- **Смена вкладок, AI-планировщик, аккаунты, синхронизация, бронирование, отзывы, чат,
  навигация, графики бюджета, массовое наращивание мест/еды** — вне позиционирования.
- **Climbing / новые магазины.** Поиск находит UNIQLO, Nike, Adidas, оба duty free и все ТЦ
  (`val_iter8`/`probe_batch2`); новых кандидатов без проверки не добавляем.

## 8. Финальный product check (ответ после реализации)

| Вопрос | Ответ |
|---|---|
| До поездки: может подготовиться? | Да — без изменений: «До поездки N дней», чек-лист, план |
| В поездке: понятно, что сегодня? | **Да (новое)** — карточка «Сегодня» первой |
| Прямо сейчас: что делать? | **Да (новое)** — «Сейчас, днём: …», «Следующее», «Подходит сейчас», `#/now` |
| Планы изменились: быстрая замена? | Да — «Если планы меняются» + «Что открыто сейчас рядом» → существующий «Заменить текущий план» |
| Поехал: адрес / такси / Amap? | Да — без изменений, из карточки места |
| Потратил: быстро записать? | Да — «+ Расход» рядом с «Сегодня» |
| В конце: фактические затраты? | Да — итоги, бюджет, «Остаток на день», расходы по пунктам дня |
| Боится потерять данные / новый телефон? | **Да (новое)** — «Мои данные»: файл, текст, импорт, откат |
| Сколько стоит план заранее? | **Нет — осознанный future scope** (§7) |
