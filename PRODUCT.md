## 0. Как пользоваться этим документом

### 0.1 Для владельца проекта

- В начале каждого нового чата прикладывайте этот файл (и, когда появится, актуальный код).
- Решение, принятое в чате, но не внесённое в этот документ, считается **неутверждённым**.
- После каждой итерации документ обновляется, а изменения записываются в журнал (раздел 17).

### 0.2 Обязательные правила для AI-ассистента

1. Прочитай документ целиком до начала любой работы.
2. Утверждённые решения (`D-xx`) не меняются молча. Изменение предлагается явно: «Предлагаю изменить D-12, потому что…» — и применяется только после согласия владельца.
3. Отклонённые варианты (`X-xx`) не предлагаются повторно без новых аргументов.
4. Гипотезы (`H-xx`) — не факты. На неподтверждённых гипотезах нельзя строить сложную логику.
5. Открытые вопросы (`Q-xx`) нельзя закрывать догадкой. Если вопрос блокирует задачу — скажи об этом прямо.
6. Факты внешнего мира (`F-xx`) имеют дату проверки. Если прошло больше 3 месяцев или факт касается въезда, оплаты, цен, расписаний, транспорта — перепроверь перед использованием.
7. Не выдумывай туристические факты. Неизвестное помечается как неизвестное.
8. Перед крупным изменением кода объясни: что делаем, зачем, какие файлы меняются, какие риски, как проверить результат.
9. Не добавляй библиотеки, фреймворки, сервисы и внешние зависимости без явного согласия владельца.
10. В конце итерации предложи правки к этому документу: что подтвердилось, что изменилось, что добавить в журнал.

## 1. Продукт

### 1.1 Формулировка

**Sanya Travel Guide** — карманный помощник на русском языке для туриста из РФ в Санье (о. Хайнань, Китай). Он работает без постоянного интернета и отвечает на вопрос **«что мне полезно сделать сейчас?»**:

- **до поездки** — что подготовить с учётом российской специфики (оплата, связь, приложения, документы, вещи);
- **на месте** — куда пойти рядом с отелем с учётом свободного времени, сил, интересов и погоды;
- **в моменте** — как объяснить таксисту, куда ехать.

### 1.2 Главный продуктовый принцип

Не «Что есть в Санье?», а **«Что мне полезно сделать сейчас?»**

### 1.3 Цель первой версии

Небольшой, красивый и реально полезный гид по Санье, которым обычный турист из РФ может пользоваться прямо со смартфона.

### 1.4 Чего продукт не делает

| Задача | Кто делает лучше | Наша роль |
|---|---|---|
| Бронирование отелей, билетов, экскурсий | Trip.com и др. | Не делаем |
| Навигация, маршруты, такси | Amap (AMAP Global) | Передаём пользователя в Amap |
| Отзывы и рейтинги заведений | Dianping, Trip.com | Не делаем |
| Продажа экскурсий | Маркетплейсы экскурсий | Не делаем, остаёмся нейтральными |

## 2. Пользователь

### 2.1 Основной пользователь (утверждено)

Русскоязычный турист из РФ, который собирается в Санью или уже находится там на отдыхе.

### 2.2 Контекст использования

- Мало времени и нет желания читать длинные инструкции.
- Интернет на месте может быть слабым, дорогим или нестабильным (см. H-09).
- Не знает китайского языка.
- Привычные инструменты (российские карты, Google-сервисы) в Китае не работают или работают плохо (F-02, F-04).

### 2.3 Два режима использования

| Режим | Где | Интернет | Главный вопрос |
|---|---|---|---|
| Подготовка | Дома, в РФ | Есть | «Что я ещё не подготовил?» |
| Поездка | В Санье | Ненадёжен | «Куда пойти сейчас?», «Как туда доехать?» |

### 2.4 Не целевые пользователи на текущем этапе

Туристы не из РФ, путешественники по другим городам Китая, бизнес-путешественники, туроператоры.

## 3. Проблема

### 3.1 Утверждённая формулировка

Информация о подготовке и отдыхе в Санье разбросана, часто устаревает и не учитывает российскую специфику, а в момент решения («куда пойти сейчас?») у туриста мало времени, слабый интернет и языковой барьер.

### 3.2 Боли, подтверждённые фактами

- **Оплата:** российские карты в Китае не работают, мобильные кошельки требуют подготовки (F-02).
- **Навигация:** Google Maps в Китае ненадёжен, нужен Amap (F-04, F-05).
- **Раздробленность информации:** русскоязычный контент распределён между SEO-статьями, блогами туроператоров, маркетплейсами экскурсий и Telegram-чатами (F-12).

### 4.2 Честная оценка

- **Русский язык сам по себе — не конкурентное преимущество.** Он есть у Visit Sanya, Trip.com, Amap (F-03, F-05, F-06).
- В бронировании, навигации и отзывах мы не конкурируем.
- **Главный риск продукта — не код, а поддержка актуальности контента одним человеком** (R-01).

## 5. Принципы (утверждено)

### 5.1 Продуктовые

- Отвечаем на «что сделать сейчас», а не просто перечисляем объекты.
- Каждая версия добавляет **одну понятную группу возможностей**, остаётся рабочей и проверяемой.
- Перед любой функцией задаём вопрос: **«Нужно ли это для текущей версии?»**
- 30 проверенных мест лучше, чем 200 сомнительных.

### 5.2 Достоверность

- Не выдумываем факты о местах, расписаниях, ценах, правилах въезда, транспорте, оплате, связи, погоде.
- У каждого факта в пользовательском контенте есть **источник** и **дата проверки**.
- Приоритет источников: официальные (госорганы, официальный сайт объекта, visitsanya.com) → крупные надёжные сервисы → проверенный личный опыт. Одного блога недостаточно для критичной информации.
- Изменчивая информация сопровождается пометкой «может измениться, проверьте актуальность».

### 5.3 UX

Простота → быстрое понимание → минимум действий → одна рука → читаемость → крупные элементы → понятная навигация → минимум перегруженности.

### 5.4 Разработка

- Самый простой рабочий вариант, который реально поддерживать одному человеку.
- Не ломаем работающий функционал; не переписываем проект без веской причины.
- Разделяем: интерфейс, логику, данные, конфигурацию, статический контент.
- Не создаём абстракций «на будущее».

### 6.1 Продукт и объём

| D-04 | Нейтральность: в MVP нет рекламы, партнёрских ссылок и продажи экскурсий. Не рекомендуем конкретные банки и платёжных посредников — даём общие принципы и источники. | Доверие; снижение риска ошибочных советов (R-03) |
| D-05 | Объём базы мест в MVP: **25–40** проверенных мест. | Качество важнее количества (R-01) |
| D-06 | Рестораны и другие конкретные точки питания (фудкорты, уличная еда) не включаются в `places.json`; в нём по-прежнему допустимы только рынки и гастроулицы (`category: "market"`). Для конкретных точек питания — отдельный, отдельно загружаемый слой `data/food.json` (9.6.4), физически не смешиваемый с `places.json`: `category`, обозначающей еду, в `config.categories`/`places.json` по-прежнему нет и не заводится. Food-карточки нейтральны так же, как места: без рейтингов, score и рекламных формулировок, `status: verified`/`draft` — как везде (D-18). *Уточнено 2026-09-16 решением владельца по итогам Итерации 8 (`ITERATION-8-CONTENT-ARCHITECTURE.md` §2.6, `ITERATION-9-CONTENT-GAP-ANALYSIS.md`; было: «Рестораны не включаем. Допустимы только рынки и гастроулицы»).* | Заведения быстро меняются, их дорого поддерживать; отдельный файл и отсутствие категории «еда» в `places.json` технически исключают попадание конкретных заведений в основную базу мест, сохраняя нейтральность (D-04) |

### 6.2 UX

| ID | Решение | Обоснование |
|---|---|---|
| D-07 | Mobile-first. Нижняя панель из **4 вкладок: «Сейчас», «Места», «Подготовка», «Справка»**. | Удобно одной рукой; ощущается как приложение |
| D-08 | Главная «Сейчас» меняется в зависимости от дат поездки: без дат / до поездки / в поездке / после поездки (раздел 8.3). | Персонализация без AI и без аккаунтов |
| D-09 | **Единый чек-лист подготовки**, сгруппированный по времени (раздел 8.7), а не отдельные списки документов и вещей. | Пользователь думает «что сделать сегодня», а не «какой это тип задачи» |
| D-10 | Фильтры — **кнопки-чипы** с мгновенным результатом и счётчиком найденного. Поиск по названию вторичен (Should). | При 25–40 местах чипы полезнее поиска |
| D-11 | «Рядом» в MVP = расстояние по прямой от **точки проживания**, без GPS. Район (`stg:trip.area`) — логический контекст, точка проживания (`stg:trip.stay`) — точка отсчёта; какую точку использовать, решает одна функция `resolveOrigin()`. Если точка не уточнена — расстояние считается от центра выбранного района, и интерфейс честно пишет «от центра района». В интерфейсе — «~N км»; то, что округляется до 0,0 км, — «менее 0,1 км». **Время в пути не показываем.** *Изменено 2026-09-13 решением владельца (было: «от выбранного района проживания», «~N км по прямой»).* | Нет запроса разрешений; нет выдуманных данных о маршрутах; центр протяжённой бухты не выдаётся за место проживания (дефект QA «~3,5 км» в Ялунване) |
| D-12 | Карточка места: сначала параметры и действия, потом текст. Обязательно: «Показать таксисту», «Скопировать название», избранное, источник и дата проверки, «Как добраться» (переход в Amap, D-02, реализовано после решения Q-03, `js/logic/amap.js`). | Действие важнее описания |
| D-13 | **«Избранное»** (`stg:saved`) — отдельный механизм сохранения мест; «Мой план» его не заменяет, избранное в план не переносится. С Итерации 6 рядом с ним есть **«Мой план»** — вторая, датированная форма (8.10). *Изменено 2026-09-13 решением владельца (было: «В MVP вместо „Моего плана“ — „Избранное“»).* | Избранное — «интересно, может быть схожу», план — «иду туда в этот день»; избранное по-прежнему закрывает 80% ценности за 10% усилий |
| D-14 | Не используем сторонние фото без лицензии. Основа — иконки категорий; с Итерации 7 допускаются фотографии со свободной лицензией (CC BY, CC BY-SA, CC0 и подобные) при проверяемой странице источника, авторе и лицензии у каждого фото (9.2): 1–2 фото на место, не больше 10 файлов, каждый ≤70 КБ, суммарно ≤600 КБ. Если легального фото не нашлось — место остаётся без фото, плейсхолдер не рисуется. *Уточнено 2026-09-13 (Итерация 7; было: «Не используем сторонние фото без лицензии. В MVP — иконки категорий»).* | Авторские права (R-06), вес офлайн-версии |
| D-15 | Интерфейс только на русском языке. Китайский текст — только как данные (названия, адреса, фразы). | Фокус D-01 |

| D-22 | Регламент перепроверки: изменчивые темы (въезд, оплата, связь, транспорт) — перед каждым публичным обновлением и **не реже раза в 3 месяца**; места — **не реже раза в 6 месяцев**. | Контент устаревает (R-01) |

## 7. Объём MVP

### Must have — без этого MVP не выпускается

1. **Первый запуск:** даты поездки и район проживания (оба шага можно пропустить и изменить позже).
2. **Главная «Сейчас»:** состояние зависит от дат (раздел 8.3).
3. **Подготовка:** единый чек-лист по этапам, прогресс сохраняется на телефоне; у критичных пунктов — отметка, источник и дата проверки.
4. **Места:** 25–40 проверенных мест; список; фильтры-чипы; сортировка по расстоянию от точки проживания (если точка не уточнена — от центра района, D-11).
5. **Карточка места:** параметры, «почему стоит», советы, «Показать таксисту», «Скопировать название», избранное, источник и дата проверки.
6. **Избранное:** сохранение мест на телефоне.
7. **Справка:** короткие карточки по базовым темам (раздел 8.8).
8. **Публикация** на GitHub Pages и проверка на реальном телефоне. *(Подготовлена в Итерации 5: относительные пути, `.nojekyll`, инструкция в `README.md`; сама публикация и проверка по ссылке ещё не выполнены.)*

### Should have — сразу после Must, до теста с пользователями

- Офлайн-режим (PWA) и установка на экран телефона (обязателен до теста с пользователями, D-29). *(Реализован в коде Итерации 5; проверка на iPhone после публикации ожидает.)*
- Поиск по названию (русскому, английскому, китайскому).
- Пометка «может измениться» у изменчивых полей.

### Could have — если останется время и подтвердится ценность

- Подборщик «У меня N часов, хочу X, не хочу много ходить» (3 вопроса, без AI — это те же фильтры). *Реализовано в Итерации 8 на `#/places` (`ITERATION-8-TIME-INTEREST-PICKER-RESULT.md`): группы «Сколько времени» / «Что интересно» / «Нагрузка», состояние — в URL (`f=`), автоматическая validation пройдена, реальные устройства не проверялись.*
- Режим «Плохая погода» на главной.
- Полезные фразы с китайским текстом для показа. *(Реализовано в Итерации 4: «Под рукой», 16 фраз из официального списка Visit Sanya.)*
- Рекомендованный план поездки и «Мой план»: взять рекомендацию целиком или по дням, изменять, переносить и менять дни местами, добавлять места в день. *(Реализовано в Итерации 6, 8.10; X-03 снято.)*

### Не делаем сейчас

Карта, маршруты, бронирование, отзывы и рейтинги, аккаунты и синхронизация между устройствами, backend, AI, погода и курсы валют онлайн, push-уведомления, другие города, другие языки интерфейса, тёмная тема.

*«План по дням» убран из списка в v1.6: реализован в Итерации 6 (8.10). Карта по-прежнему отложена (X-02). «Рестораны» убраны из списка в v1.8: сами рестораны как категория `places.json` по-прежнему не делаются (D-06), но конкретные точки питания с Итерации 8 существуют отдельным минимальным слоем «Еда» внутри `#/places` (`data/food.json`, 9.6.4) — без рейтингов, score и рекламы, как и всё остальное.*

С Итерации 6: «Мой план» `#/plan`, его день `#/plan/<date>`, перенос или обмен дня `#/plan/<date>/move`, рекомендованный план `#/recommended` и его день `#/recommended/<date>` — вложенные экраны Главной (подсвечена «Сейчас»); выбор дня для места `#/place/<id>/plan` (подсвечены «Места»); параметр `addTo=<date>` у `#/places` и `#/place/<id>` — выбор места для дня (8.10). С Итерации 8: раздел «Еда» — второй режим вкладки «Места» (`#/places?mode=food`, переключатель «Места» / «Еда», D-06, 9.6.4), не отдельный маршрут и не пятая вкладка; экран «Показать таксисту» для точки питания — `#/places/food/<id>/taxi`, возврат — «← Назад» на `#/places?mode=food`. Кнопки возврата — «← Назад», «← К моему плану», «← К рекомендации», «← К месту». Пятой вкладки нет (D-07).

### 8.2 Первый запуск

1. Экран 1: «Когда поездка?» — даты начала и окончания. Кнопка «Пропустить».
2. Экран 2: «Где вы живёте?» — выбор района из `config.json`. Кнопки «Пока не знаю» и «Пропустить».
3. Переход на главную. Данные можно изменить в `#/settings` (доступ с главной).

### 8.3 Главная «Сейчас» — состояния

| Состояние | Условие | Что показываем |
|---|---|---|
| Без дат | Даты не заданы | Предложение указать даты; прогресс подготовки; быстрые сценарии поездки |
| До поездки | Сегодня раньше даты начала | «До поездки N дней»; «Готово X из Y»; до 3 ближайших невыполненных дел (сначала критичные) из уже начавшихся этапов; кнопка «Весь чек-лист» |
| В поездке | Дата начала ≤ сегодня ≤ дата окончания | «День N из M · район»; кнопки сценариев: «Рядом с отелем», «Есть 2–3 часа», «Хочу природу», «В помещении (дождь или жара)» — при известной точке отсчёта показывают только места в радиусе 20 км (`NEAR_RADIUS_KM`, Q-21) с плашкой «Показать все»; **«🍜 Поесть рядом»** (`js/views/home.js`, добавлено после Итерации 9) — единственная точка входа в раздел «Еда» с Главной, ведёт на `#/places?mode=food&near=1`; сохранённые места; «Под рукой» (телефоны, фразы, адрес для таксиста) и быстрый доступ к справке (такси, экстренные номера) |
| После поездки | Сегодня позже даты окончания | Нейтральное состояние и предложение изменить даты |

Каждая кнопка сценария открывает список мест с заранее включёнными фильтрами.

**Блок «Мой план»** (Итерация 6) — одна карточка-ссылка; смотрит только на «Мой план» (`stg:myplan`), период берётся из `data/plan.json`. Сегодня в периоде и в плане есть день → «Сегодня по плану» с заголовком дня; сегодня пусто → «Сегодня ничего не запланировано»; план пуст → «План поездки не начат» со ссылкой на рекомендованный план. Вне периода в состоянии «До поездки» — ссылка «План поездки», в остальных состояниях блока нет. В поездке блок стоит под кнопками сценариев. Полный день на Главной не дублируется, рекомендация не подменяет личный план. Если `plan.json` недоступен, блока нет, остальная Главная работает.

### 8.4 Места: список и фильтры

**Строка списка:** название (рус.), иконка категории, «~N км» (если есть точка отсчёта — см. «Расстояние» ниже), длительность, нагрузка.

**Чипы MVP:**

| Чип | Логика |
|---|---|
| Рядом | Сортировка по расстоянию от точки отсчёта (D-11). Если район не выбран — предложить выбрать; если район выбран, а точка не уточнена — сортировать от центра района и предложить уточнить. *Отдельным чипом не реализуется — сортировка по умолчанию (`MVP-UX-SPEC.md` §4)* |
| До 2 ч | `durationHours[0] ≤ 2` |
| Пляжи / Природа / Культура / … | По `category` |
| Легко | `effort = "low"` |
| В помещении | `setting = "indoor"` |
| Бесплатно | `price.type = "free"` |
| С детьми | Есть тег `kids` |
| Сохранённые | Только места из избранного |

**Правило сочетания:** чипы категорий объединяются через «ИЛИ» (пляжи или природа); разные группы — через «И» (природа и легко и до 2 ч). Над списком — «Найдено N». Если ничего не найдено — подсказка, какой фильтр снять.

**Расстояние:** считается по прямой (формула гаверсинусов) от точки отсчёта до `location` места; район самого места в расчёте не участвует.

Точка отсчёта (`resolveOrigin()`, D-11), по приоритету:

| № | Источник | Точность (`precision`) | Как подписано |
|---|---|---|---|
| 1 | `stay.source = "gps"` / `"manual"` — координата | `exact` | «от места проживания» |
| 2 | `stay.source = "spot"` — ориентир из `config.areas[].spots` выбранного района | `exact` | «от места проживания» |
| 3 | Точки нет или ориентир не найден, у района есть `center` — **запасной вариант** | `area` | «от центра района» + плашка в списке «Расстояния — от центра района, это приблизительно. Уточнить, где вы живёте» |
| 4 | Район не выбран или у него нет центра (`other`) | `none` | Расстояние не показывается |

**Формат:** сначала округление до 0,1; если результат 0 — «менее 0,1 км»; если меньше 10 — с одним знаком после запятой («~3,4 км»); иначе — целым числом от исходного значения («~27 км»; 9,96 км → «~10 км»). Формат меняет только текст — сортировка идёт по исходным километрам.

Строка 1 таблицы приоритета (`stay.source = "gps"/"manual"`) остаётся частью схемы `stg:trip.stay` (9.7), но интерфейса, который бы её заполнял, по-прежнему нет: `#/settings` (Итерация 3) позволяет выбрать только `spot`. Заявленная в предыдущих версиях документа связка «GPS-точка → точка проживания» этой строкой не реализована.

**«Рядом со мной» (GPS, Итерация 8, `js/views/places.js`, `ITERATION-8-NEARBY-IMPLEMENTATION-RESULT.md`)** — отдельный, самостоятельный блок над списком, не чип и не часть `resolveOrigin()`/D-11: по нажатию запрашивает `navigator.geolocation`, разово получает координату и показывает verified-места в радиусе `NEAR_RADIUS_KM` (20 км) от неё, отсортированные по расстоянию. Координата живёт только в памяти экрана, **не пишется в `stg:trip.stay`** и не переживает переход на карточку места и возврат назад — это осознанное решение реализации (приватность и простота), а не подключение к строке 1 таблицы выше; отдельное явное решение владельца о такой интеграции не принято (Q-22). Точность геолокации «в поле» не проверена (R-08 остаётся открытым).

**Подборщик «Время + интерес + нагрузка» (Итерация 8, `ITERATION-8-TIME-INTEREST-PICKER-RESULT.md`)** — форма над списком: время (3 варианта), интерес (6, по `category`), нагрузка (необязательно, 3). Полностью заменяет ручной набор чипов, состояние — в URL (`f=`), совместим с `near=1`. См. 7 (Could have).

**«N км от вас» (на карточке места/еды, `js/logic/geo.js`, добавлено после закрытия Итерации 9)** — третий, отдельный от «Рядом со мной» механизм: одна и та же геопозиция запрашивается один раз за сессию (без нового диалога разрешения, если оно уже выдано) и используется только для строки «N км от вас» на карточке — не влияет на сортировку списка, точку проживания или `resolveOrigin()`. Координата не пишется в `localStorage`.

### 8.5 Карточка места — порядок блоков

1. Название (рус.) и китайское название под ним; кнопка избранного.
2. Чипы-параметры: длительность, нагрузка, на улице / в помещении, цена.
3. «~N км от места проживания» (`precision: exact`) или «~N км от центра района» (`precision: area`); без точки отсчёта блока нет (8.4).
4. Короткое описание (1 фраза) и «Почему стоит» (2–3 пункта).
5. Кнопки: **«Показать таксисту»** (главная), «Скопировать название», «Открыть в Amap» (после Q-03).
6. Лучшее время, часы работы, цена (текстом) — с пометкой «может измениться».
7. Советы.
8. Подвал: «Проверено: <месяц год> · Источник: <ссылка>».

С Итерации 6 после «Почему стоит» — кнопка «Добавить в мой план» (→ выбор дня `#/place/<id>/plan`); в режиме выбора места для дня — «Добавить на <дату>». «Показать таксисту» остаётся главной закреплённой кнопкой.

С Итерации 7 между блоком 3 (расстояние) и блоком 4 (описание) — необязательный блок фото: 1–2 фотографии (поле `photos[]`, 9.2), под каждой подпись «Фото: автор · лицензия» с ссылкой на страницу источника; следом — необязательная строка-ссылка «Больше фото и подробнее — <ресурс>» (поле `more`), тач-цель ≥44 px. У места без фото и без `more` блока нет; ссылка `more` показывается и без фото. После «Советов», перед подвалом — необязательный раскрывающийся блок «Что здесь интересного» (поле `story`), свёрнут при каждом открытии карточки; у места без `story` блока нет. Оба блока не сдвигают действия по D-12 и не мешают «Показать таксисту» оставаться закреплённой кнопкой.

### 8.6 Экран «Показать таксисту»

Полноэкранный режим: китайское название и адрес на китайском максимально крупным шрифтом, под ними мелко — русское название. Работает без интернета. Кнопка «Закрыть» и «Скопировать».

### 8.8 Справка — темы MVP

1. Въездная карта (Arrival Card, с Итерации 7) — что это, когда заполнять, официальный адрес Государственного миграционного управления КНР (NIA), предупреждение о поддельных платных сайтах, что взять с собой, оговорка про освобождённые категории. Первая карточка в списке.
2. Оплата (с учётом российских карт).
3. Связь и интернет.
4. Передвижение: такси и Amap.
5. Экстренные номера и помощь.
6. Сезон и климат (включая сезон дождей и тайфунов — формулировки только по источникам).

**«Под рукой»** (`#/handy`, Итерация 4) — первая строка списка «Справки», но не карточка для чтения, а действия в один тап: адрес проживания → «Показать таксисту»; 11 контактов по группам, вся строка — ссылка `tel:` (номер отдельным текстом не дублируется); 16 фраз → фраза на весь экран. Без адреса — пустое состояние со ссылкой в `#/settings`. Тексты карточек справки при этом не менялись, кроме `CONTENT-ITERATION-4.md` §5.1–5.2.

**«О приложении»** (Итерация 5) — последний блок «Справки»: дисклеймер отдельной карточкой (Q-12, текст владельца) и строка «Версия <CACHE_VERSION> · данные обновлены: <самая поздняя verifiedAt>».

### 8.9 Общие UX-требования

- Зона нажатия — не меньше 44×44 px.
- Основной текст — не меньше 16 px; хорошая контрастность.
- Главные действия — в нижней половине экрана.
- Нет горизонтальной прокрутки страницы.
- Пустые состояния всегда подсказывают следующее действие.
- Любое действие даёт видимую реакцию (отметка, счётчик, сообщение).

### 8.10 Рекомендованный план → Мой план (Итерация 6)

Два независимых слоя (`ITERATION-6-RESEARCH.md` v3.0, `ITERATION-6-IMPLEMENTATION.md`):

| | Рекомендованный план | Мой план |
|---|---|---|
| Где хранится | `data/plan.json` — статический контент (D-16), меняет только владелец | `stg:myplan` в `localStorage` — локальное состояние пользователя (D-17, 9.7) |
| Меняется действиями пользователя | Никогда | Да |
| Экраны | `#/recommended`, `#/recommended/<date>` | `#/plan`, `#/plan/<date>`, `#/plan/<date>/move`, `#/place/<id>/plan` |

- **Рекомендация:** период 13–26 ноября 2026 (14 календарных дней, 27.11 не входит). У дня — тип, заголовок, одна фраза, утро / день / вечер, места (ссылки на `places.json` по `id`, до 3), советы, «если не хочется». Экран рекомендации: «Следовать плану на 100%», «В мой план» у каждого дня, отметка «✓ в моём плане», блоки «Почему план такой» и «Если устали», дата проверки и источники. Тексты описывают намерение — без цен, часов и расписаний: проверяемые факты живут в карточках мест.
- **«Мой план» существует сразу;** пустой план и пустой день — валидные состояния. Действия: взять день или весь план (непустой план — с вопросом «Заменить весь план?»), взять день из рекомендации заново, очистить, перенести, поменять местами, добавить место. Для занятого дня выбор «Добавить» / «Заменить» обязателен. Мест в дне — не больше 3.
- **Полная копия, а не список отличий:** обновление рекомендации не меняет уже принятые дни. Уведомления «рекомендация обновилась» нет (отложено).
- **День из одних мест валиден:** заголовок — названия мест; отсутствующие поля не выводятся; удалённые и черновые места пропускаются молча.
- **Добавить место в день** можно с карточки места («Добавить в мой план» → выбор дня) или начиная с дня («Добавить место» → «Места» в режиме выбора → карточка → «Добавить на <дату>» → возврат в день). Прямое открытие адреса с `addTo` режим выбора не включает.
- **25 ноября** рекомендация предлагает выезд с пометкой «самый лёгкий день для отказа»; изменить его — действие пользователя в приложении, а не правка данных.
- Главная — 8.3. Работает офлайн. Не делаем: ввод своего текста, drag-and-drop, почасовое планирование, несколько планов, уведомления, синхронизация.

### 9.3 Определения значений

**`effort`:**
- `low` — ходьба до ~1 км по ровной поверхности, без подъёмов;
- `medium` — прогулка 1–3 км или заметные подъёмы/лестницы;
- `high` — длительная ходьба, трекинг, крутые подъёмы.

**`setting`:** `outdoor` — всё на улице; `indoor` — в основном в помещении, подходит в дождь и жару; `mixed` — есть и то и другое.

**`price.type`:** `unknown` ставится, если источник не даёт однозначного ответа. Не угадываем.

Ориентир — точка, от которой пользователь может считать расстояние, если живёт рядом с ней («У пляжа Ялонг Бэй»); это не отель. ### 9.6.3 План (`plan.json`, Итерация 6)

Период и число дней берутся только из данных — в коде дат нет. Цены, часы работы и расписания в плане не пишутся (D-21, D-22).

### 9.6.4 Точка питания (`food.json`, Итерация 8)

Отдельный от `places.json` слой (D-06, `ITERATION-8-CONTENT-ARCHITECTURE.md` §2.2/3.2): конкретные рестораны, фудкорты и уличная еда, которым не место в основной базе мест. Массив, как `contacts.json`/`phrases.json`, но со `status` — записи будут появляться из сырого research с неполными данными.

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `id` | строка | да | Латиница, дефисы, уникально, не меняется |
| `status` | `draft` \| `verified` | да | Черновики не показываются (D-18); `loadFood()` возвращает только `verified` |
| `name.ru` / `name.zh` | строки | да | Названия |
| `addressZh` | строка | да | Адрес на китайском — для «Показать таксисту» (переиспользует общий `taxi.js`) |
| `area` | id из `config.areas` | да | Тот же справочник районов, что и у мест |
| `kind` | `restaurant` \| `foodcourt` \| `street-food` | да | Тип точки питания; отдельный маленький enum, не `config.categories` — категория, обозначающая еду, в `places.json`/`config.categories` не заводится (D-06) |
| `location.lat` / `location.lng` | числа | нет | WGS-84 (D-19); может отсутствовать (`null`) у ещё не отгеокодированной записи — тогда запись остаётся `draft` |
| `priceLevel` | `budget` \| `mid` \| `unknown` | нет | Грубая оценка цены, не точные чеки |
| `hours` | строка | нет | Часы работы текстом (D-21) |
| `note` | строка | нет | 1 фраза: что это и чем отличается — только проверенные факты, без рекламных формулировок и рекомендаций конкретного оператора как «лучшего» |
| `sources` | массив `{title, url}` | да | Минимум один источник (D-18) |
| `verifiedAt` | дата `ГГГГ-ММ-ДД` | да | Дата последней проверки (D-18) |

Полей «рейтинг», «отзывы», «score» или «меню» в схеме нет и не будет: нейтральность (D-04) и принцип «не выдумываем факты» (5.2) запрещают показывать оценку без представительной выборки отзывов, которой ни у одного кандидата нет (`ITERATION-8-CONTENT-VERIFICATION.md`). Food-раздел живёт внутри вкладки «Места» как второй режим (`#/places?mode=food`, переключатель «Места» / «Еда»), а не отдельным пунктом нижней навигации (D-07: пятой вкладки нет); у food-записи есть «Показать таксисту» (`#/places/food/<id>/taxi`), «Как добраться» (переход в Amap, `js/logic/amap.js`, Q-03) и с записи с координатами — «N км от вас» (8.4); полей `durationHours`/`effort`/`setting` и кнопки «Добавить в мой план» у неё по-прежнему нет. *Добавлено 2026-09-17, после закрытия Итерации 9: у food также есть собственное «Рядом со мной» (Food Nearby, `js/views/food.js`, отдельная от places реализация того же GPS-механизма и того же `NEAR_RADIUS_KM`) — точка входа с Главной, «🍜 Поесть рядом» (8.3).*

### 9.7 Состояние пользователя (`localStorage`)

| Ключ | Содержимое |
|---|---|
| `stg:schema` | Версия схемы, начинаем с `1` |
| `stg:trip` | `{ "start": "ГГГГ-ММ-ДД", "end": "ГГГГ-ММ-ДД", "area": "yalong", "stay": { "source": "spot", "spotId": "yalong-beach-front" }, "home": { "addressZh": "海南省三亚市…", "nameRu": "Отель" } }` |
| `stg:checklist` | `{ "<id пункта>": true }` |
| `stg:saved` | `["<id места>", …]` |
| `stg:installHintDismissed` | `"1"` — подсказка «Добавьте на экран „Домой“» закрыта (Итерация 5). Отдельный флаг, к `stg:trip` не относится, `stg:schema` остаётся `1` |
| `stg:myplan` | «Мой план» (Итерация 6): `{ "planId": "yalong-2026-11", "days": { "2026-11-24": { "placeIds": ["luhuitou-park"], "origin": "user" } } }` |

**`stg:trip.stay`** — необязательная точка проживания (`null`, если не уточнена). `source: "spot"` хранит только `spotId` (координата берётся из справочника, D-20); `source: "manual"` / `"gps"` хранит `point` WGS-84 (у `gps` — ещё `updatedAt`); интерфейс Итерации 3 создаёт только `spot`. Смена района в настройках сбрасывает `stay`. Старое значение без `stay` читается как `stay: null`, `stg:schema` остаётся `1`. Повреждённый `stay` читается как «точки нет» без перезаписи хранилища.

**`stg:trip.home`** (Итерация 4, Q-15) — необязательный адрес проживания для экрана «Показать таксисту»: `{ addressZh, nameRu? }`, ввод вручную в `#/settings` (в обычном режиме; первый запуск остаётся двумя блоками). Это не точка отсчёта: координаты у адреса нет, расстояния по-прежнему по `stay` и `resolveOrigin()`. Пустой адрес = `null`; смена района адрес не сбрасывает; приложение адрес не проверяет. Значение без `home` читается как `home: null`, `stg:schema` остаётся `1`; повреждённый `home` — «адреса нет» без перезаписи хранилища.

**`stg:myplan`** (Итерация 6) — локальное состояние пользователя, полная копия его плана (8.10). `days` — объект «дата → день»; отсутствие даты = пустой день. Поля дня — те же, что в `plan.json` (без `date`), плюс `origin`: `recommended` (день взят из рекомендации) или `user` (создан или изменён пользователем). Запись и чтение — через белый список полей; мест в дне не больше 3. Нет ключа — пустой план; повреждённое значение читается как пустой план без перезаписи хранилища. Отдельный ключ, `stg:schema` остаётся `1`, миграций нет. Обновление приложения и рекомендации `stg:myplan` не меняет.

Если пункт чек-листа, место или ориентир удалены из контента, связанная отметка молча игнорируется (для ориентира — расстояние считается от центра района).

### 10.3 Правила разделения

- `views/` только отображают и обрабатывают нажатия; не содержат бизнес-логики.
- `logic/` не обращается к странице (DOM) — только принимает и возвращает данные.
- Данные загружаются только через `data.js`, состояние пользователя — только через `storage.js`.
- Тексты интерфейса, которые могут меняться, по возможности хранятся в `config.json`, а не в коде.

### 10.4 Запреты (D-28)

Не подключаем во время работы приложения: внешние шрифты, CDN-библиотеки, Google-сервисы, внешние карты, стороннюю аналитику, внешние изображения. Всё, что нужно приложению, лежит в репозитории.

### 10.5 Путь развития платформы

Web App → PWA (офлайн и установка на экран, Итерация 5) → при необходимости упаковка в Android/iOS (например, Capacitor). Backend появляется только при реальной необходимости: AI (Итерация 10), синхронизация между устройствами, сбор обратной связи.

### 10.6 Критерии готовности каждой итерации

1. Работает на iPhone (Safari), Android (Chrome) и в Яндекс Браузере (D-31).
2. Нет ошибок в консоли браузера.
3. Весь функционал предыдущих итераций проверен вручную по списку и не сломан.
4. Все показываемые данные соответствуют правилам D-18.
5. Изменения опубликованы на GitHub Pages и открываются по ссылке с телефона.
6. PRODUCT.md обновлён, журнал изменений заполнен.

## 16. Словарь

| Термин | Значение в проекте |
|---|---|
| Место | Туристический объект в базе `places.json` |
| Район | Часть Саньи из справочника `config.areas`; логический контекст пользователя («живу в Ялунване»). Центр района — только запасная точка отсчёта расстояний |
| Точка проживания | `stg:trip.stay`: откуда считать расстояния — ориентир района, позже координата (GPS / вручную) |
| Ориентир (`spot`) | Проверенная точка внутри района из `config.areas[].spots`, которую пользователь выбирает в «Где именно?» |
| Рекомендованный план | Статический план поездки по дням из `data/plan.json`; меняет только владелец (8.10) |
| Мой план | Личный план пользователя по датам в `stg:myplan`; берётся из рекомендации целиком или по дням и меняется пользователем (8.10) |
| Тип дня | Значение из `config.planDayTypes`: прилёт, пляж, лёгкий день, выезд, шопинг, отъезд |
| Этап | Временная группа пунктов чек-листа (раздел 8.7) |
| Критичный пункт | Пункт, без которого поездка под угрозой (`critical: true`) |
| Изменчивая информация | Данные, которые могут измениться: въезд, оплата, цены, расписания (`volatile: true`) |
| Черновик | Запись со `status: "draft"`; пользователю не показывается |
| PWA | Веб-приложение, которое можно установить на экран телефона и использовать без интернета |
| Service Worker | Скрипт `sw.js`, который кладёт файлы приложения в кэш браузера и отдаёт их без сети |
| Precache / `CACHE_VERSION` | Явный список файлов для офлайна в `sw.js` / версия кэша: её смена = выпуск обновления |
| WGS-84 / GCJ-02 | Международная система координат (GPS) / китайская система координат со смещением |
| Hash-роутинг | Переключение экранов через часть адреса после `#` |
| localStorage | Память браузера на телефоне пользователя |
