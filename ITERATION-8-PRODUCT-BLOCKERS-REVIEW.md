## Q-18 — Underwater World

### Current rule

`config.json.categories` содержит `nature` и `entertainment` как раздельные, взаимоисключающие значения (`place.category` — одно значение, D-20: справочник закрыт, новых значений без владельца не добавить). Q-18 сформулирован в `CONTENT-ITERATION-4.md` §6.6 и повторён без изменений в `NEXT-ITERATION-CONTENT-RESEARCH.md` (C-1) и `ITERATION-8-CONTENT-BATCH-1-RESULT.md` (строка 33, 140): «Категория — nature или entertainment?». Решение не принято ни разу за четыре итерации.

### Facts

- **Самопозиционирование объекта:** официальная страница Visit Sanya (`visitsanya.com/destination/yalong-bay-underwater-world`) относит объект к разделу «Natural Scenery» (自然风光) — источник хорошего качества для факта категоризации на стороне источника.
- **Фактический сценарий посещения:** по этой же официальной странице и по независимому агрегатору (cncn.com, вспомогательно) — это центр платных водных активностей: дайвинг (380–480 CNY), гидроцикл (180 CNY), полупогружная лодка (220 CNY), парасейлинг, снорклинг, каяки. Пассивного «природного» осмотра (тропа, вид, парк) в описании нет.
- **Соответствие текущей схеме:** `config.json` описывает `nature` как «Природа» — по фактическому использованию в базе (`luhuitou-park`, `yalong-tropical-forest-park`, «Долина роз Ялонг Бэй») это парки и природные территории для прогулки/осмотра, не купленные активности. `entertainment` пока не занята ни одной записью — прецедента использования нет.
- Это не вопрос факта о мире: категория — элемент собственного справочника продукта (`config.categories`), а не характеристика места. Несовпадение с рубрикатором стороннего сайта не является фактической ошибкой (сформулировано в `CONTENT-ITERATION-4.md` §6.6).

### Implications

- Сценарий «Хочу природу» (8.3) при выборе `nature` выдаст пользователю дайв-центр вместо парка/пляжа — расходится с ожиданием пользователя, который просил именно природу для спокойного времяпрепровождения.
- При выборе `entertainment` категория перестаёт быть пустой (сейчас, до решения, в ней нет ни одной подтверждённой записи — единственный кандидат, C-1, заблокирован именно этим вопросом), а фильтр «Хочу природу» остаётся содержательно честным.
- Пока Q-18 не решён, запись `yalong-bay-underwater-world` не может существовать даже в статусе `draft`: любая запись обязана указать `category` (обязательное поле, 9.2), значит любое сохранение записи в файл уже стало бы решением за владельца.

### Options for owner

1. **`entertainment`.** Аргумент: соответствует фактическому сценарию посещения (платные активности, а не осмотр природы); сохраняет честность фильтра «Хочу природу» для остальных мест категории. Минус: расходится с классификацией официального источника (не является фактической ошибкой, см. выше).
2. **`nature`.** Аргумент: совпадает с самопозиционированием официального источника, ничего не переопределяет. Минус: размывает практический смысл фильтра «Хочу природу» — пользователь получит дайв-центр вместо парка.

Третьего варианта (новая категория) в рамках текущей схемы нет: `config.categories` — закрытый справочник (D-20), добавление нового значения — отдельное архитектурное решение, не предмет этого вопроса.

## D-04 — Commercial operators

### Current rule

D-04 (`PRODUCT.md` 6.1): «Нейтральность: в MVP нет рекламы, партнёрских ссылок и продажи экскурсий. Не рекомендуем конкретные банки и платёжных посредников — даём общие принципы и источники.» Формулировка написана применительно к платёжным посредникам и не содержит прямого правила для коммерческих достопримечательностей (аквапарки, тематические парки, школы серфинга) — отсюда сам блокер: неясно, распространяется ли она на них и как именно.

### Atlantis

Aquarium при курортном комплексе Atlantis Sanya — частный курортный оператор. Официальный сайт объекта (`atlantis.com/sanya`) не отдал содержимого при попытке получения текста; часы (10:00–19:00) и цена (178/128 CNY) — только по агрегатору (unconfirmed), не по официальному источнику. Помимо блокировки D-04, есть отдельная нерешённая проблема источника: данные ниже принятого порога качества для этого проекта независимо от исхода D-04.

### Haichang

Тематический парк Haichang Fantasy Town. Адрес и телефон подтверждены официальной страницей Visit Sanya, но часы работы конфликтуют: 10:00–22:00 (официально) vs 12:00–23:00 (агрегатор) — не устранено. Тот же вопрос нейтральности, что у Atlantis: крупный коммерческий тематический парк.

### Houhai surfing

Деревня Хоухай (后海村) — не оператор, а локация с мягкой волной и песчаным дном, сезон для новичков ноябрь–март (совпадает с датами запланированной поездки 13–26 ноября). У Visit Sanya отдельной официальной страницы нет; координата в OSM — точка деревни, а не пляжа для сёрфинга (неверная для сценария); адреса нет ни в одном источнике. Сама активность подразумевает платные частные школы — вопрос нейтральности возникает, только если карточка называет и рекомендует конкретную школу; описание локации как таковой (пляж, волна, сезон) этой проблемы не создаёт.

### Options for owner

Возможные формулировки D-04 применительно к коммерческим достопримечательностям (для фиксации, не выбор за владельца):

1. **Место как нейтральный факт vs выбор оператора.** Разрешить карточку места, описывающую само место (адрес, часы, что там происходит) как городской объект, без оценочных слов («лучший», «стоит», «выгодно»), без цен активностей, без ссылки на сайт оператора и без формулировок, подталкивающих к покупке конкретного пакета/абонемента. Тогда Atlantis и Haichang попадают в базу на общих основаниях с прочими платными достопримечательностями (Наньшань, лесопарк Ялонг Бэй), при условии решения проблемы качества источников (часы/цена) отдельно от D-04.
2. **Разграничение «место» и «оператор/продавец».** Карточка места описывает физический объект и то, что там можно сделать в целом (аквариум с рыбами, тематический парк с шоу; серфинг на пляже с мягкой волной), но никогда не называет и не выбирает конкретного продавца услуги внутри места (конкретную дайв-школу, конкретный серф-клуб, конкретный тариф). Для Houhai это означает: можно описать пляж/деревню и условия для серфинга; нельзя рекомендовать конкретную школу. Для Atlantis/Haichang это уже выполняется автоматически, так как сам объект и есть место (не выбор среди операторов).
3. **Единое правило для всех трёх.** «Коммерческая природа объекта (курортный аквариум, тематический парк, платная активность на пляже) сама по себе не является причиной исключения; исключается только продвижение конкретного продавца/бренда/тарифа, отсутствующее в остальных карточках базы (без цен на билеты, без оценочных слов, без ссылок на покупку).» Это фактически формализует уже действующую практику карточек мест (D-12: «почему стоит» без промо, цена — текстом с пометкой «может измениться», без ссылки на покупку) и не требует нового отдельного правила под каждый случай.

## Q-17 — Duty-free / shopping

### Current rule

Q-17 сформулирован в `CONTENT-ITERATION-4.md` §6.7: развилка между D-06 (запрещает рестораны, разрешает рынки/гастроулицы — к duty-free моллу отношения не имеет напрямую) и D-04 (нейтральность в отношении рекламы/партнёрских ссылок/продажи). Текущий текст D-04 не называет шопинг-моллы прямо; вопрос — распространяется ли принцип нейтральности на «нейтральную информационную карточку» о молле как городском объекте. Решение отложено владельцем 2026-09-13 (зафиксировано в `CONTENT-ITERATION-4.md` и подтверждено нерешённым в `NEXT-ITERATION-CONTENT-RESEARCH.md` C-14 и `ITERATION-8-CONTENT-BATCH-1-RESULT.md` строки 46, 139, 205).

### Facts

- Категория `shopping` уже объявлена в `data/config.json` (`{ "id": "shopping", "name": "Покупки", "icon": "shopping" }`) и в `planDayTypes` — это существующая, но пустая часть справочника; в `places.json` категория `shopping` не используется ни одной записью.
- `plan.json` уже ссылается на шопинг-сценарий текстом (день 23.11 «Шопинг и вечерняя программа»), не привязанный ни к одной карточке места — то есть продуктовый сценарий шопинга уже присутствует в контенте, только без места-опоры.
- Единственный найденный кандидат, CDF Sanya International Duty Free City, подтверждён только агрегатором (bendibao) — ни адреса, ни часов из официального источника не найдено; это отдельная, самостоятельная проблема качества источника, не связанная напрямую с Q-17.

### Implications

- Категория `shopping` архитектурно уже существует (D-20 удовлетворён — справочник объявлен); включение первой записи с этой категорией не требует изменения `config.json`, только новой записи в `places.json`. То есть это не архитектурное расширение, а применение уже принятой модели.
- Без решения Q-17 категория `shopping` останется пустой строкой в фильтрах — пользователь увидит чип/раздел без единого результата (или он не появляется вовсе, если чипы рендерятся только для непустых категорий — это деталь реализации, не проверялась в рамках этого review).
- Решение Q-17 в пользу «разрешить с ограничением» создаёт прецедент, применимый к любому будущему обычному торговому/гастрономическому объекту: нейтральная карточка (адрес, часы, что это, без цен, оценок и ссылки на покупку) — так же, как уже сделано для рынков (см. `sanya-first-market`: `price.note` = «платите только за покупки», нет оценочных слов, нет ссылки на конкретных продавцов).

### Options for owner

1. **Разрешить с ограничением** (рекомендация исследования, `CONTENT-ITERATION-4.md` §6.7): включать как факт городской инфраструктуры — без оценок, без цен товаров/скидок, без ссылки на сайт магазина. `why` — только то, что подтверждено официальным источником. Требует дополнительно решить проблему качества источника для CDF отдельно (адрес/часы сейчас только по агрегатору).
2. **Запретить.** Категория `shopping` остаётся пустой до появления другого типа кандидата (не duty-free molл), либо не используется вовсе.
3. **Разрешить только неторговый шопинг-контекст.** Например, включать шопинг-локации только как часть уже существующих карточек (рынки, гастроулицы) без отдельной категории для крупных ТЦ/дьюти-фри — тогда Q-17 закрывается отказом именно для крупных коммерческих моллов, а не для шопинга как темы вообще.

## D-06 — Markets / gastro streets

### Current rule

D-06 (`PRODUCT.md` 6.1): «Рестораны не включаем. Допустимы только рынки и гастроулицы.» Обоснование: заведения быстро меняются, дорого поддерживать. Прецедент применения — `sanya-first-market` (категория `market`, `verified`): продуктовый рынок, официально описанный как место с уличной едой вечером, без указания конкретных точек питания или их цен.

### Baihuagu

Yalong Bay Central Square и торговая улица Baihuagu (C-8) — по вторичным источникам (Baidu Baike, турагентские страницы) Baihuagu описана как «торгово-ресторанная зона напротив отеля Тяньюй с международной и местной кухней» — то есть по факту это зона с ресторанами, а не рынок в смысле `sanya-first-market` (продукты/сувениры, покупка товаров). Официальной страницы Visit Sanya для этих двух объектов не найдено; источники ниже минимального порога качества (Baike и турфирменные сайты, не официальный источник и не крупный надёжный сервис). Отдельно неясно, является ли сама площадь (Central Square) общественным городским пространством или частью коммерческой территории отеля — это не установлено ни одним источником.

### Ganghua Night Market

Ночной рынок Ганхуа (港华夜市, C-15) — концептуально ближе к D-06 (ночной рынок с едой, аналог модели «рынок днём / уличная еда вечером» уже принятой для `sanya-first-market`). Официальная страница Visit Sanya существует, но не содержит ни адреса, ни китайского названия, ни часов — только текстовое описание. Адрес и часы («18:00 – около 04:00») найдены только у одного агрегатора низкого приоритета. Это тот же класс проблемы, что уже возникал и не был закрыт с Первым рынком (`CONTENT-ITERATION-4.md` §7: «Выбирать адрес наугад нельзя»), не специфичный для D-06 как правила, а специфичный для качества источника.

### Options for owner

D-06 сам по себе (правило про рынки/гастроулицы) не блокирует Ganghua Night Market — блокирует отсутствие второго независимого источника для адреса. Реальная развилка — только по Baihuagu:

- Минимальное уточнение, которое позволило бы отличать «рынок/гастроулицу» (допустимо) от «ресторанной зоны при отеле» (недопустимо по духу D-06): формальный признак — рынок/гастроулица описывает совокупность точек питания и товаров как единое общественное пространство без выделения конкретных заведений (по аналогии с `sanya-first-market`, где нет названий конкретных точек питания и цен), тогда как «ресторанная зона» в источниках описывается через отдельные рестораны/кухни как отличительный признак.
- По этому критерию Baihuagu (описана источниками именно через «международную и местную кухню» как набор заведений) ближе к запрещённому классу, чем к разрешённому — но качество источников для этого вывода ниже принятого порога, поэтому окончательный вывод по Baihuagu зависит и от D-06, и отдельно от решения не оформлять записи по источникам ниже порога (это уже действующее правило 5.2, не требует отдельного решения владельца).
- Такое уточнение не расширяет D-06 на рестораны как класс — оно лишь формализует уже фактически применённый в `sanya-first-market` критерий «рынок = совокупность, не отдельные заведения».

## D-01 — Geographic scope

### Current rule

D-01 (`PRODUCT.md` 6.1): «Фокус: Санья + турист из РФ. Другие города и аудитории — только после проверки ценности.» Граница задана по формулировке «Санья», без явного определения — административный округ Санья (地级市) или более широкая туристическая зона. В существующей базе (`config.json.areas`) все районы (`dadonghai`, `yalong`, `sanya-bay`, `haitang`, `city`) физически находятся в городском округе Санья.

### Binglanggu

Binglanggu Li & Miao Cultural Heritage Park физически расположен в уезде Баотин (保亭黎族苗族自治县自治县三道镇甘什岭槟榔谷) — административно отдельная единица, не входящая в городской округ Санья, около 20 км от Ялунваня. Источники по фактам (часы, телефон, цены) — хорошего качества (официальный сайт объекта binglanggu.com + Visit Sanya + агрегатор для цены), проблема исключительно географическая, не в качестве данных.

### Implications

- Формально Binglanggu — уже выход за существующую границу D-01, если границу трактовать буквально как «городской округ Санья». Все текущие записи в `places.json` не создают такого прецедента.
- Если владелец разрешит Binglanggu как «разумное расширение зоны Саньи» (обоснование: находится в типичном радиусе однодневной экскурсии из Саньи, туристически воспринимается как часть «поездки в Санью»), это меняет фактическую границу D-01 с «городской округ» на «зона в пределах дневной поездки от Саньи» — более мягкий, но и более субъективный критерий.
- Единообразие базы: `Daxiaodongtian` (C-5, ~50 км, но в пределах округа Санья) и `Yazhou Ancient City` (C-9, ~50 км, тот же коридор) уже находятся близко к границе субъективного «далеко ли это ещё Санья», хотя формально в округе. Разрешение Binglanggu не создаёт для них нового вопроса (они и так в округе), но создаёт прецедент оценки «дальности» по времени/расстоянию поездки, а не по административной границе — это может вызвать похожие вопросы у будущих кандидатов ещё дальше (курорт Улучжичжоу уже в базе; более дальние объекты, например, Учжичжоу-подобные острова или объекты в Линшуй/Made соседних уездах, не встречались в исследовании, но логически станут следующим шагом того же вопроса).

### Options for owner

1. **Оставить границу по административному округу Санья.** Binglanggu — SKIP независимо от качества данных, до отдельного решения о расширении фокуса продукта (потенциально отдельная итерация/эксперимент, не точечное исключение).
2. **Разрешить как «зона дневной поездки из Саньи».** Тогда нужно сформулировать явный критерий (например, «в пределах ~1 часа на машине от курортных зон Саньи»), чтобы не решать вопрос заново по каждому будущему кандидату за пределами округа.

## Cross-cutting observations

- **Q-17 и D-04 разблокируются независимо друг от друга**, но оба движутся в сторону одной и той же формулировки: «нейтральная информационная карточка коммерческого объекта — без цен/оценок/ссылок на покупку — допустима». Если владелец примет такую формулировку один раз (например, решая D-04), она по аналогии закрывает и Q-17, и наоборот. Стоит рассматривать их как одно решение о принципе, а не два отдельных.
- **D-04 одним решением разблокирует три кандидата** (Atlantis, Haichang, Houhai) — это самый «дорогой» по последствиям блокер из пяти.
- **D-06 фактически не блокирует Ganghua Night Market** — там проблема качества источника, а не правила; уточнение D-06 нужно только для Baihuagu.
- **Даже после решения владельца часть кандидатов останется недооформленной** по независимым причинам качества источника: Atlantis (часы/цена только по агрегатору, сайт объекта не открылся), Haichang (конфликт часов), Houhai (нет адреса, координата не там), Ganghua (адрес по одному источнику низкого приоритета), CDF (все факты по агрегатору). Решение блокеров не equals готовности записи — по каждому кандидату из этого списка, скорее всего, потребуется отдельный раунд проверки фактов после снятия продуктового блокера.
- **D-01 — единственный блокер с прецедентным эффектом за пределами одного кандидата**: решение по Binglanggu задаёт правило для любого будущего объекта вне городского округа Санья, а не только для этой записи.
