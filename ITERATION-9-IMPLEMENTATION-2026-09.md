## 2. «Сегодня» и «Сейчас»

### 2.1 Семантика дат (почему «сегодня» не бывает ложным)

В приложении две независимые даты: `stg:trip.start/end` (пользователь; «День N из M», состояния
Главной) и период рекомендации `plan.json → meta` (13–26.11.2026). Карточка «Сегодня» появляется,
только если **одновременно**: Главная в состоянии «В поездке» (по `stg:trip`), сегодняшняя дата
внутри периода плана (`resolveToday`) и в «Моём плане» на эту дату есть непустой день. Иначе —
прежний блок плана («Сегодня ничего не запланировано» / «План поездки не начат» / ничего).

| Ситуация | Что видит пользователь |
|---|---|
| До поездки | «До поездки: N дней», чек-лист, «План поездки» — без изменений |
| День поездки, день в плане есть | Карточка «Сегодня» |
| День поездки, день пуст / план не начат | Прежняя карточка-ссылка |
| Даты поездки не совпадают с периодом плана | «День N из M», без карточки «Сегодня» |
| После поездки / без дат | Прежние состояния, «сегодня поездки» не показывается |

«Сегодня» — локальная дата устройства, «сейчас» — локальные часы устройства (`localMoment()`),
без сети. Прибытие (13.11) — обычный день плана с одним вечерним текстом: утром карточка покажет
«Дальше, вечером: заселение…».

### 2.2 Карточка «Сегодня» (`renderTodayCard`)

- «Сегодня по плану · чт, 19 ноября» + заголовок и тип дня (ссылка на день).
- **Сейчас / Дальше** по ритму дня (`rhythmNow`): утро до 12:00, день до 17:00, вечер после.
  Если у текущей части нет текста — строки «Сейчас» нет, «Дальше» — ближайшая следующая часть с текстом.
- **Пункты дня** (экскурсии, затем места — тот же порядок, что в заголовке дня) с кнопкой «✓»
  (44×44, `aria-pressed`), меткой «Следующее» у первого не отмеченного и «Открыто до …» у мест
  с подтверждёнными часами. Всё отмечено — «Всё из плана на сегодня отмечено ✓».
- «Завтра: <заголовок>» (или «ничего не запланировано»), если завтра в периоде.
- Вход в день — сам заголовок карточки со стрелкой «›». Отдельную ссылку «Открыть день ›» убрали
  после замера: на 320×568 без неё «Сейчас», «Дальше» и первый пункт дня остаются над нижней
  панелью (проверка в `val_iter9.py`), «+ Расход» — сразу под сгибом.
- В день вылета — блок «✈️ День вылета» (§6).

### 2.3 Отметки «сделано» — `stg:plandone`

```json
{ "v": 1, "days": { "2026-11-19": ["excursion:wuzhizhou-island-trip", "place:luhuitou-park"] } }
```

Отдельный слой поверх плана; `stg:myplan` не меняется ни байтом (тест). Ключ пункта — тот же вид
`kind:id`, что у ссылки расхода. Отметки ставятся на «Сейчас» и на экране дня (сегодня и прошедшие
дни; будущее и рекомендация — без кнопок). При замене/переносе дня отметки удалённых пунктов
просто не находят себе пункта и не показываются — хранилище не чистится, данные не теряются,
второго источника истины нет. Повреждённое значение читается как «ничего не отмечено» без
перезаписи ([I3-4]).

### 2.4 «Подходит сейчас» и `#/now` — детерминированные правила

`nowCandidates(places, { moment, origin, radiusKm = 20, exclude })`:

1. Места из сегодняшнего плана исключаются (их и так видно в «Сегодня»).
2. Если известна точка отсчёта (`resolveOrigin`: точка проживания или центр района) — только
   места в радиусе `NEAR_RADIUS_KM` (20 км), сортировка по расстоянию; без точки — порядок файла
   и плашка «Указать район».
3. Статус часов (`getOpenStatus`):
   - нет структуры → раздел **«Часы не подтверждены»** (никогда не «открыто»);
   - открыто и до закрытия ≥ `durationHours[0]` часов (минимум на месте) или круглосуточно →
     **«Открыто и успеете»**;
   - иначе (закрыто, выходной, перерыв, временно закрыто, не успеть) → не показывается, счётчик
     «Не показаны: N мест с известными часами…».
4. Фильтры `#/now`: «В помещении» (`setting = indoor`), «Легко» (`effort = low`), «До 2 ч»
   (`durationHours[0] ≤ 2`) — те же предикаты, что у чипов «Мест» (`applyFilters`), состояние в
   `f=`, `replaceState` без роста истории.
5. Строка: иконка категории, название, статус, «~N км · длительность · нагрузка · улица/помещение».
   **Времени в пути нет** (X-12) — экран прямо об этом пишет в «Как подбираем».

На Главной — до 3 первых кандидатов и «Что ещё можно сделать сейчас ›». На экране дня (сегодня)
в «Если планы меняются» — «🕒 Что открыто сейчас рядом».

Отклонённые альтернативы: взвешенный «скоринг» (непрозрачен), время в пути по прямой (выдумка),
показ неизвестных мест как «вероятно открыто» (нарушает правило безопасности).

## 3. Структурированные часы — `openingHours`

Необязательное поле места **рядом** с текстовым `hours` (обратная совместимость: все потребители
`hours` работают как раньше, текст по-прежнему показывается в карточке).

```json
"openingHours": {
  "weekly": { "mon": [["09:00","23:00"]], "tue": [["13:00","23:00"]], …, "sun": [["09:00","23:00"]] },
  "verifiedAt": "2026-09-25"
}
```

| Возможность | Как записывается |
|---|---|
| Обычный график | `weekly`, все 7 дней обязательны |
| Выходной день | `"mon": []` |
| Перерыв (split) | `[["08:00","12:00"],["15:00","18:00"]]` |
| Через полночь | `[["18:00","02:00"]]` (закрытие раньше открытия); хвост учитывается на следующий день |
| До конца суток | `"24:00"` |
| Сезоны | `seasons: [{ from: "03-01", to: "09-30", weekly }, { from: "10-01", to: "02-29", weekly }]` — через Новый год, 29 февраля покрыто |
| Круглосуточно | `always: true` — только если источник прямо так говорит |
| Временное закрытие | `closures: [{ from, to, note }]` — перекрывает любой график, «Временно закрыто: …» |
| Неизвестно | поля нет → «Часы не подтверждены» |

Невалидная структура целиком читается как «неизвестно» (не как частично верная). Праздничные
изменения в `weekly` не записываются — только в `closures`, если есть официальное объявление.
Валидатор данных проверяет схему, наличие текстового `hours` и `verifiedAt`.

## 4. Копия данных: экспорт / импорт

### 4.1 Формат (schemaVersion 1)

```json
{
  "app": "sanya-travel-guide",
  "kind": "user-data-backup",
  "schemaVersion": 1,
  "exportedAt": "2026-11-19T08:40:00.000Z",
  "appVersion": "v15",
  "data": {
    "stg:trip": {…}, "stg:checklist": {…}, "stg:saved": […], "stg:myplan": {…},
    "stg:plandone": {…}, "stg:expenses": {…}, "stg:budget": {…}
  }
}
```

- `data` — ключи `localStorage` как есть, значения — как хранятся (сырой JSON), только
  существующие ключи. **Не входят:** контент `data/*.json`, `stg:schema`, подсказка установки,
  аварийные копии `…:backup`.
- `appVersion` — `CACHE_VERSION` активного Service Worker (`getAppVersion()`), `null` без SW —
  версия не дублируется константой в коде.
- Файл: `sanya-guide-backup-ГГГГ-ММ-ДД.json`.

### 4.2 Экран «Мои данные» (`#/data`)

Вход — из «Настроек поездки» и из «Расходов» («Сохранить копию всех данных ›»); в первом запуске
— «Восстановить данные из копии» (новый телефон). Блоки: что сейчас хранится (счётчики),
**Скачать файл копии** (Blob + `download`), **Отправить файл копии…** (Web Share с файлом — только
если браузер умеет `canShare({files})`), **Скопировать копию как текст** (буфер; текст готовится
заранее, чтобы запись в буфер шла в том же нажатии — требование iOS), **Выбрать файл копии** /
**вставить текст** → предпросмотр → «Заменить мои данные».

«Скопировать отчёт» у расходов оставлен: это текст для человека (мессенджер, попутчики), копия —
для машины. Объединять их не стали.

### 4.3 Проверки импорта и безопасность

1. `JSON.parse` (BOM допускается) → «Не удалось импортировать: файл повреждён или это не JSON».
2. Конверт: `app`, `kind`, целый `schemaVersion ≥ 1` → иначе «это не копия данных Sanya Travel Guide».
3. `schemaVersion` больше поддерживаемого → «копия сделана более новой версией приложения».
4. Неизвестные разделы `data` пропускаются и называются в предпросмотре; нет ни одного известного — ошибка.
5. Каждый раздел проходит **тот же белый список**, что и обычная запись (`storage.normalizeSection`
   → `normalizeMyPlan`, `normalizeExpensesState`, …). Раздел не того типа — «повреждён, пропущен»;
   повреждённые записи внутри раздела отбрасываются и **считаются** («повреждённых пропущено: 1»).
6. Предпросмотр: дата копии, версия, что будет заменено (с количествами), что не изменится.
   Ничего не пишется до «Заменить мои данные».
7. Запись (`applyUserData`): сначала снимок текущих данных (в формате копии) в `stg:import:backup`,
   затем разделы; ошибка на любом шаге (переполнение, запрет) возвращает все затронутые ключи.
8. Семантика — **замена по разделам**: разделы из копии заменяются, отсутствующие в копии не
   трогаются. Слияния нет (детерминированно и предсказуемо).
9. «Вернуть как было до импорта» — восстанавливает снимок целиком (ключи, созданные импортом,
   удаляются), затем снимок удаляется; «Удалить этот снимок» — вручную.

### 4.4 Версии и миграции

`migrateBackup()` — таблица шагов «версия → следующая», сейчас пустая (версия одна); копия текущей
версии возвращается как есть (идемпотентно, тест). Новый формат добавит шаг — старые файлы
продолжат читаться. Схема `localStorage` не менялась: `stg:schema` остаётся `1`, новый ключ
`stg:plandone` несёт свою версию внутри (`v: 1`) — прецедент `stg:expenses`. Старая версия
приложения (v14) новый ключ не знает и не трогает (проверено в `val_pwa_v15.py`).

## 5. Расходы в дне и бюджет

- **Расходы за день по пунктам плана:** при наличии привязанных расходов — строки «<пункт> — сумма»
  и «Без привязки к плану — сумма», затем сами записи (нажатие — правка; после сохранения/удаления
  возврат в день). Связь — существующее поле `expense.link`, новых связей не заводили. Замена дня
  связь не рвёт: расход остаётся привязан к пункту, подпись берётся из контента.
- **«Остаток на день»** = фактический остаток бюджета ÷ оставшиеся дни поездки (включая сегодня;
  до поездки — все дни). Не показывается без бюджета, без дат, после поездки и при перерасходе.
  Это не прогноз: будущие траты не угадываются.

## 6. День вылета (минимальный departure mode)

В день с типом «Отъезд» в плане или в последний день `stg:trip` — блок «✈️ День вылета» внутри
«Сегодня» (или отдельно, если дня в плане нет) со ссылками только на **уже проверенный контент**:
«Доставка и хранение багажа» (сдать багаж в отеле, забрать в аэропорту), «Беспошлинные покупки»
(выдача в аэропорту), «Возврат НДС при выезде», «Итоги расходов поездки». Новых фактов об
аэропорте (время регистрации, запас времени, адрес для такси) не добавлено: целевой проверки
официальных источников в этом запуске не было, выдумывать нельзя.

## 8. Производительность

Новых зависимостей нет. «Подходит сейчас» — один проход по 52 местам при рендере Главной
(`getOpenStatus` — десятки операций на место); часы не кешируются и не хранятся. Экспорт — один
`JSON.stringify` пользовательских ключей. Лишних сетевых запросов нет: всё через Promise-кэш
`data.js` и precache SW.
