## 3. «Подготовка» — недостающий Must-have (checkbox vs строка)

### Требование

Разделить два независимых действия на строке пункта чек-листа:

1. **Тап по чекбоксу** (собственная зона нажатия ≥44×44px) → **только** переключает состояние «выполнено/не выполнено» данного пункта. Не открывает детали.
2. **Тап по телу строки** (заголовок пункта, зона вне чекбокса, тоже ≥44×44px) → открывает экран/оверлей с деталями пункта.

### Содержимое экрана деталей

Показывать поля пункта из `checklist.json` (схема 9.5), которые для него заданы:
- `title` (заголовок)
- `details` — если поле присутствует у пункта
- `sources` — если поле присутствует (обязательно для `critical: true` и `volatile: true`, по схеме)
- `verifiedAt` — если присутствует
- пометка «Может измениться» — если `volatile === true`

Если необязательное поле у конкретного пункта отсутствует — соответствующий блок в деталях просто не рендерится, ошибок это не должно вызывать.

### Что нельзя ломать

- Существующий прогресс (`stg:checklist` в `localStorage`) — открытие деталей не должно изменять состояние выполнения.
- Аккордеон по этапам — поведение раскрытия/сворачивания этапов не меняется.
- Существующие ключи `localStorage` (`stg:schema`, `stg:trip`, `stg:checklist`, `stg:saved`) — новых ключей для «деталей» не создавать, состояние экрана деталей не персистентно (не нужно запоминать, был ли он открыт).
- Mobile-first: без горизонтального скролла, вертикальный скролл без вложенных скролл-контейнеров.

### Реализация — что не фиксируется этим документом

Конкретный UI-паттерн экрана деталей (модальное окно, оверлей, отдельный вложенный маршрут) — на усмотрение реализации. Если используется отдельный hash-маршрут, он обязан следовать уже существующему паттерну роутинга и корректно работать с кнопкой «Назад» браузера (без повторения history loop, уже исправленного в post-4B патче).

### Acceptance criteria

- [ ] Тап по чекбоксу переключает `checked`-состояние пункта и не открывает детали.
- [ ] Тап по любому месту строки вне чекбокса открывает детали пункта.
- [ ] Открытие/закрытие деталей не изменяет `stg:checklist` в `localStorage`.
- [ ] Экран деталей показывает `details`, `sources`, `verifiedAt`, пометку `volatile`, если эти поля заданы у пункта; отсутствующие поля не отображаются и не ломают экран.
- [ ] У критичных пунктов (`critical: true`) в деталях виден их источник и дата проверки (если заданы по схеме).
- [ ] Обе зоны нажатия (чекбокс и тело строки) ≥44×44px и не перекрывают друг друга неоднозначно.
- [ ] Прогресс, аккордеон и сохранение в `localStorage` работают как раньше.

## 4. Validation

**Checklist / детали пункта**
- [ ] Тап по чекбоксу меняет только состояние выполнения, детали не открываются.
- [ ] Тап по телу строки открывает детали, чекбокс не переключается.
- [ ] Детали показывают все заданные для пункта поля (`details`, `sources`, `verifiedAt`, `volatile`), отсутствующие поля скрыты без ошибок.
- [ ] Закрытие экрана деталей возвращает к списку без потери состояния аккордеона.

**Progress / localStorage**
- [ ] Прогресс («Готово X из Y») пересчитывается корректно после отметки пункта.
- [ ] Закрыть браузер, открыть заново — прогресс на месте (`stg:checklist` не потерян).
- [ ] Ключи `stg:schema`, `stg:trip`, `stg:saved` не затронуты изменениями в «Подготовке».

**Accordion**
- [ ] Раскрытие/сворачивание этапов работает как раньше, без регрессий.

**«Справка» (info)**
- [ ] `data/info.json` загружается, все 5 карточек (`payment`, `connectivity`, `taxi-amap`, `emergency`, `climate`) отображают актуальный (после правок) текст.
- [ ] Карточка `climate` показывает обновлённый `summary`, согласованный с points 6 и 7.
- [ ] Пометка «Может измениться» отображается корректно (`volatile: true` у всех пяти).
- [ ] Источники (`sources`) кликабельны, ведут на правильные URL, touch target ≥44px.

**Routing / Navigation**
- [ ] `#/info` → `#/info/<id>` → «Назад» → `#/info` работает без history loop.
- [ ] Кнопка «Назад» браузера работает корректно на `#/info/<id>` и (если использован маршрут) на экране деталей пункта чек-листа.
- [ ] Нижняя навигация (4 вкладки) видима и рабочая на всех экранах, включая новый экран деталей пункта.

**Общее**
- [ ] Нет горизонтального скролла страницы ни на одном из затронутых экранов.
- [ ] Touch targets ≥44×44px везде, где это применимо (чекбокс, тело строки, ссылки источников, «Назад»).
- [ ] Нет ошибок в консоли браузера.
- [ ] Работает в Safari (iOS), Chrome (Android), Яндекс Браузер (D-31).
- [ ] Регрессия: «Справка» и «Подготовка» из 4B/post-4B патча продолжают работать без изменений в тех частях, которые не затронуты этим closeout.
