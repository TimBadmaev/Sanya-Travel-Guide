# Passport v1 — closeout

*2026-10-10 · основа: `EXPLORER-PASSPORT-SPEC.md` (v1.1) и решения владельца Q-P1…Q-P6 (`PRODUCT.md` D-33) · ветка `main` @ `51aaad4`, изменения не закоммичены.*

## 1. Итог

«Паспорт исследователя» работает как часть приложения: посещение verified-места отмечается вручную в карточке места, к нему пишется заметка до 200 символов, на экране `#/passport` видны посещения, заметки, 12 наклеек с прогрессом и части побережья. Наклейки и прогресс вычисляются из отметок и текущего каталога. Покупки (`shopping`) отмечаются только на память. Паспорт входит в «Мои данные» и работает офлайн после установки Service Worker (`v16`).

**Не реализовано (следующий этап):** декоративная SVG-схема побережья, экраны частей побережья, альбом, анимации, баннер «С прошлого раза», изменение даты отметки, учёт отметок «сделано» плана (последнее — только после отдельного решения, D-33).

## 4. Решения при реализации

- **Части побережья, а не районы.** ID спецификации `dadonghai`, `yalong`, `haitang` совпадали с `config.areas` — заменены на `coast-*`; `prepareContent` отбрасывает часть побережья с ID района.
- **Исключение покупок — одно правило.** `rewardCatalog()` отсекает `shopping` до всех расчётов наград (наклейки, прогресс мест, знаменатели частей побережья, достижимость, подсказки). Наклейка с условием `category: "shopping"` прошла бы проверку контента, но стала бы недостижимой и скрылась — обойти исключение нельзя (это проверено тестом).
- **Наклейка острова — необязательная** (`optional: true`): не входит в «из 11», без подсказок, с пометкой «Необязательная».
- **«Над бухтой» → «Охотник за видами».** Решение владельца требовало убрать утверждение о виде «сверху» из описания; название несло то же утверждение, поэтому переименовано и оно. ID не менялся. Если название нужно вернуть — это одна строка в `passport.json`.
- **Дата** подписана как «Отмечено · 19 ноября 2026».
- **Подсказки** показываются у двух закрытых наклеек, ближайших к получению (как в спецификации 3.2): с подсказками у всех двенадцати экран на 375 px был длиной ~5 600 px.
- **Откат импорта по версии снимка.** Без этого «Вернуть как было до импорта» к снимку, снятому версией v15, стёр бы паспорт: прежний код удалял все ключи, которых нет в снимке.

## 6. Хранение, копия и офлайн

- `stg:passport` = `{ v: 1, visits: { "<placeId>": { date, at?, note? } }, seen: {} }`. Запись — синхронно при каждом действии, через белый список. `stg:schema` остаётся `1`.
- Повреждённое значение читается как пустое и не перезаписывается при чтении; перед первой записью поверх него (в том числе импортом) сырой текст один раз сохраняется в `stg:passport:backup`.
- Отметка места, которого нет в каталоге или которое стало draft, не показывается и не считается, но остаётся в хранилище.
- Копия: раздел `stg:passport` экспортируется и импортируется, `schemaVersion` 1. Старая копия без раздела паспорт не трогает. «Вернуть как было» удаляет только разделы, известные версии снимка.
- Офлайн: паспорт работает без сети **после** того, как приложение один раз открылось с сетью и SW установил кэш `v16`. Первый запуск без сети по-прежнему невозможен.
- Обновление `v15` → `v16` не меняет `localStorage` (проверено).

## 7. Оставшиеся ограничения

1. Декоративная схема, части побережья отдельными экранами, альбом, анимации, «С прошлого раза» — следующий этап (Q-P1).
2. Отметки «сделано» плана не становятся посещениями (Q-P2).
3. Дату отметки нельзя изменить: отметка «задним числом» получает сегодняшнюю дату.
4. Известный пробел вне задачи: импорт поверх **повреждённого** `stg:expenses` не сохраняет его сырую копию (у паспорта это сделано). Не исправлено — вне объёма.
5. Реальные устройства (D-31) — не проверены.
6. `logic/passport.js` больше ориентира спецификации (18 КБ против 12 КБ).
