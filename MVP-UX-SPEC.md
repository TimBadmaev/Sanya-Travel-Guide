## 2. Information Architecture (финал)

4 вкладки закрывают 4 разных пользовательских режима и совпадают с ментальной моделью «подготовка vs на месте» (2.3 `PRODUCT.md`).

| Вкладка | Назначение | Главный сценарий | Контент | Основные действия |
|---|---|---|---|---|
| **Сейчас** (`#/`) | Точка входа, контекстный ответ на «что делать сейчас» | «Открыл телефон в перерыве — что дальше?» | Состояние по датам (раздел 3), прогресс, сценарии | Перейти к делу/месту, открыть настройки поездки |
| **Места** (`#/places`) | Каталог для целенаправленного выбора | «Хочу решить, куда пойти» | Список 25–40 мест, чипы, счётчик найденного | Фильтровать, открыть карточку, сохранить |
| **Подготовка** (`#/prepare`) | Чек-лист сборов и документов | «Что мне нужно сделать до отъезда» | Этапы, пункты, прогресс | Отметить пункт, открыть детали пункта |
| **Справка** (`#/info`) | Справочные знания без действий | «Как тут вообще платить / звонить в скорую» | 5 карточек тем | Открыть карточку темы |

**Вложенные экраны:** `#/place/<id>` — карточка места · `#/place/<id>/taxi` — «Показать таксисту» · `#/info/<id>` — карточка справки · `#/settings` — даты и район (доступ иконкой с экрана «Сейчас»).

## 3. Главный экран «Сейчас» — 4 состояния (финал)

Задача экрана — ответить за 3–5 секунд без скролла.

### Без дат
1. Заголовок-приветствие (нейтральный)
2. «Укажите даты — покажем то, что актуально сейчас» + кнопка → `#/settings`
3. Прогресс подготовки, если что-то уже отмечено (иначе блок скрыт)
4. 2–3 кнопки быстрых сценариев («Хочу на пляж», «Хочу природу», «Куда сходить с детьми») — ведут в «Места», не требуют дат

### До поездки
1. «До поездки: N дней» + район, если выбран
2. «Готово X из Y»
3. До 3 ближайших невыполненных пунктов чек-листа (сначала критичные), тап открывает деталь пункта на месте
4. Кнопка «Весь чек-лист» → `#/prepare`

### В поездке
1. «День N из M · <район>»
2. 4 кнопки-сценария: «Рядом с отелем», «Есть 2–3 часа», «Хочу природу», «В помещении» — каждая открывает «Места» с предустановленными фильтрами
3. «Сохранено: N мест» → фильтр «Сохранённые», если есть избранное
4. Быстрый доступ снизу: «Такси и Amap», «Экстренные номера»

### После поездки (финал — решение №4)
**Отдельного экрана нет.** Используется тот же компонент, что «Без дат», с одной изменённой строкой текста: «Поездка завершена — даты можно обновить для следующей поездки». Смысл D-08 (Главная реагирует на даты) не теряется — состояние по-прежнему определяется датами, меняется только то, что оно не требует отдельной вёрстки.

## 4. «Места»

### Экран списка
**Сверху:** «Найдено N», ряд чипов-фильтров (горизонтальный скролл), список.

**Строка элемента:** название (рус.) · иконка категории · «~N км» (если есть точка отсчёта) · длительность · нагрузка.

**Расстояние и сортировка** (D-11, `PRODUCT.md` 8.4). Точку отсчёта выбирает `resolveOrigin()`; экран знает только точку и её точность `precision`. Список сортируется от ближнего по исходным километрам; формат — «менее 0,1 км» / «~3,4 км» / «~27 км».

| `precision` | Когда | «~N км» и сортировка | Плашка над результатами |
|---|---|---|---|
| `exact` | Выбран ориентир («Где именно?») или есть координата | Да, от точки проживания | Нет |
| `area` | Район выбран, точка не уточнена (или ориентир исчез из справочника) | Да, от центра района | «Расстояния — от центра района, это приблизительно. **Уточнить, где вы живёте**» → `#/settings` |
| `none` | Район не выбран | Нет, порядок файла | «**Выберите район, чтобы видеть расстояние**» → `#/settings` |
| `none` | Район `other` (нет центра) | Нет, порядок файла | «Для района «Другое / за пределами центральных районов» расстояние не считается — у него нет центра на карте.» (без ссылки) |

«Готово» в настройках, открытых по плашке, возвращает в список с теми же фильтрами и прокруткой; числа и порядок пересчитываются.

### Финальный набор чипов (решение №1 применено)

| Чип | Статус | Комментарий |
|---|---|---|
| Категории (Пляжи/Природа/Культура/…) | Оставляем | ИЛИ-логика внутри группы |
| До 2 ч | Оставляем | |
| Легко | Оставляем | |
| В помещении | Оставляем | Для сценария «плохая погода» |
| Бесплатно | Оставляем | |
| Сохранённые | Оставляем | |
| С детьми | Оставляем условно | Если тег `kids` наберёт < 5 мест в Итерации 0 — убрать чип, оставить обычным тегом |
| **Рядом** | **Убран.** Сортировка по расстоянию — поведение по умолчанию, когда есть точка отсчёта (точка проживания или центр выбранного района). Если район не выбран — плашка-приглашение «Выберите район, чтобы видеть расстояние» → `#/settings`, не тапаемый фильтр; остальные варианты плашки — в таблице выше |

Комбинирование фильтров — без изменений: категории через ИЛИ, остальные группы через И. При 0 результатах — подсказка, какой из последних применённых фильтров снять (нужен порядок применения в состоянии экрана — деталь для кодинг-чата, не для `localStorage`).

## 5. Карточка места (финал — решение №3 применено)

1. Название (рус.) + китайское название под ним, кнопка избранного (сердце) в углу
2. Чипы-параметры: длительность, нагрузка, улица/помещение, цена
3. «~N км от места проживания» (`precision: exact`) / «~N км от центра района» (`precision: area`); без точки отсчёта блока нет. Пример: «менее 0,1 км от места проживания»
4. Одна фраза описания + «Почему стоит» (2–3 пункта)
5. Лучшее время, часы работы, цена текстом — с пометкой «может измениться»
6. Советы
7. Подвал: «Проверено: месяц год · Источник»
8. **Внизу экрана, закреплено (sticky):** «Показать таксисту» — основная кнопка · «Скопировать название» — вторичная

«Показать таксисту» больше не строка в общем ряду кнопок — это главное CTA экрана, не теряется при скролле описания. Согласуется с H-03 (одна из самых ценных функций) и с 8.9 `PRODUCT.md` («главные действия — в нижней половине экрана»), конфликтов нет.

### Экран «Показать таксисту»
- Полноэкранный, без нижней навигации
- Центр — китайское название и адрес, крупный шрифт (не меньше 28–32px, тест на солнце)
- Мельче — русское название
- Внизу — «Скопировать» и «Закрыть»
- **Офлайн:** экран не делает сетевых запросов, рендерится из уже загруженных в память данных. Работает в авиарежиме в текущей сессии уже в Итерации 2; работа после полного перезапуска без связи — Итерация 5 (Service Worker, D-29; *номер исправлен 2026-09-13, `PRODUCT.md` v1.5*). Это разграничение уже верно отражено в критериях проверки Итераций 2 и 4 — менять не нужно.

## 6. «Подготовка»

**`#/prepare`:** общий прогресс-бар вверху, затем аккордеон по этапам — текущий и следующий этап развёрнуты, остальные свёрнуты со счётчиком «X из Y».

**Внутри этапа:** сначала критичные пункты, затем остальные. Пункт — чекбокс, заголовок, бейдж «важно» у критичных. Тап по строке открывает детали: пояснение, источник, дата проверки, пометка «может измениться» у `volatile: true`.

Единый список на уровне данных (D-09) остаётся верным решением — раскрытие аккордеоном ограничивает то, что видно единовременно, без разделения на отдельные списки (что отклонено в X-01).

## 7. «Справка»

5 тем без изменений (8.8): Оплата, Связь и интернет, Передвижение (такси и Amap), Экстренные номера, Сезон и климат.

**Формат:** список карточек на `#/info` (иконка + заголовок + 1 фраза) → тап открывает `#/info/<id>` с 3–7 пунктами, источниками, датой проверки, пометкой «может измениться».

## 8. First Run (финал — решение №2 применено)

**Один экран, два необязательных блока:**
1. «Когда поездка?» — даты начала/окончания (необязательно)
2. «Где вы живёте?» — район из справочника (необязательно). Если у выбранного района есть ориентиры (`spots`), под ним появляется вложенный необязательный подвопрос **«Где именно?»**: ориентиры района и последним — «Не знаю — считать от центра района» (по умолчанию). Блоков по-прежнему два; смена района сбрасывает ориентир
3. Одна кнопка **«Готово»**
4. Отдельная ссылка мельче **«Пропустить всё»**
5. Переход на Главную сразу в правильном состоянии (без дат / до поездки — в зависимости от того, что заполнено)
6. Изменить данные позже — иконка настроек на Главной → `#/settings`, та же форма

Приложением можно пользоваться полностью без заполнения — это уже так по конструкции (D-08, «без дат» — полноценное состояние).

## 9. Навигация — основные User Flows

1. `Главная (в поездке) → «Рядом с отелем» → Места (сорт. по расстоянию) → Карточка → Показать таксисту`
2. `Главная (до поездки) → пункт чек-листа в списке «3 ближайших дела» → детали пункта → отметить → Главная (прогресс обновлён)`
3. `Первый запуск → Пропустить всё → Главная (без дат) → Места → чип «Пляжи» → Карточка`
4. `Главная (в поездке) → «В помещении» → Места (indoor) → Карточка → В избранное`
5. `Места → Карточка → В избранное (сердце) → Места → чип «Сохранённые» → место в списке`
6. `Справка → «Оплата» → чтение карточки → назад на Справку`
7. `Главная → иконка настроек → изменить даты → Главная (состояние меняется на «до поездки»)`

*Координаты центров районов — заполняются и проверяются в Итерации 0 (Q-02 остаётся открытым до этого). Фактические значения — `data/config.json` и `CONTENT-PLACES.md` §2; ориентиры — `CONTENT-PLACES.md` §2.1. `spots` необязательны: у `haitang` и `other` их нет.*

### `places.json`
Обязательные для MVP: `id, status, name.ru, name.zh, addressZh, area, category, location, summary, why, durationHours, effort, setting, price.type, sources, verifiedAt`.
Необязательные: `name.en, tags, price.note, hours, bestTime, tips`.
Правило черновика (9.8): любое поле с «НУЖНО ПРОВЕРИТЬ» или нулевые координаты → `status: draft`, не показывается.

### `checklist.json`
Поля без изменений (9.5). `phase` определяет группировку в аккордеоне (раздел 6); `topic` в MVP нигде не отображается отдельным фильтром — задел на будущее.

### `info.json`
Без изменений (9.6).

### `localStorage`
По 9.7: `stg:schema`, `stg:trip`, `stg:checklist`, `stg:saved` — четыре отдельных ключа. Обновление прогресса не требует перезаписи всего состояния. `stg:trip` = `{ start, end, area, stay }`, где `stay` — необязательная точка проживания (`null` / `{ source: "spot", spotId }` / `{ source: "manual" | "gps", point }`); схема остаётся `1`, значение без `stay` читается как `stay: null`.

**При обновлении контента:** удалённое место/пункт чек-листа — связанная отметка молча игнорируется при рендере.
**При смене схемы (`stg:schema`):** старые данные читаются по правилам старой версии, если возможно; иначе сбрасывается только затронутый ключ, а не всё состояние. Конкретные правила миграции — точечно, при первом реальном изменении схемы.

## 12. Empty / Error / Edge cases

| Ситуация | Поведение |
|---|---|
| Нет дат | Состояние «Без дат» — не ошибка, полноценный режим |
| Нет района | «Места» без сортировки по расстоянию и без «~N км»; сценарии, требующие точки отсчёта («Рядом с отелем»), сначала ведут в `#/settings` |
| Район выбран, точка не уточнена | Расстояния и сортировка от центра района; плашка «Расстояния — от центра района, это приблизительно. Уточнить, где вы живёте»; на карточке «~N км от центра района»; «Рядом с отелем» ведёт в «Места» |
| Район `other` | Расстояний нет; нейтральная плашка без ссылки; «Рядом с отелем» ведёт в `#/settings` |
| Ориентир удалён из справочника | Молча считаем от центра района (как «точка не уточнена»), значение в хранилище не трогаем |
| Место совпадает с точкой отсчёта | «менее 0,1 км» (а не «~0,0 км») |
| Нет найденных мест (фильтры) | «Ничего не найдено» + подсказка, какой фильтр снять |
| Нет избранных мест | В чипе «Сохранённые» — пустое состояние с подсказкой |
| Нет интернета при первой загрузке | С Итерации 5: данные в офлайн-кэше — ошибки нет; данных в кэше нет — «Нет соединения. Откройте приложение один раз с интернетом, чтобы оно снова заработало офлайн.» + «Повторить». Прочие ошибки загрузки — прежнее «Не удалось загрузить данные» |
| Данные не загрузились (ошибка формата) | То же сообщение, без технических деталей |
| Пользователь удалил данные браузера | `localStorage` пуст → ведёт себя как при первом запуске |
| Место стало недоступно (удалено) | Просто исчезает из списка/избранного при следующей загрузке контента |
| Данные давно не обновлялись | Не обрабатывается кодом — ответственность владельца по D-22; видно пользователю через дату «Проверено: …» |

## 13. Mobile UX — контрольный список

- Тапаемые элементы — не меньше 44×44px
- Основной текст 16px+, на экране «Таксисту» — 28px+
- Главные действия — в нижней половине экрана или закреплены снизу
- Китайский текст в адресах — без обрезания, с переносом строк
- Никакого горизонтального скролла страницы (кроме рядов чипов)
- Список мест и чек-лист — вертикальный скролл, без вложенного скролла внутри вложенного

## 14. Контент vs код — граница

| Код (JS/CSS/HTML) | Контент (JSON) |
|---|---|
| Логика фильтрации, сортировки, расчёта расстояния | Сами места, их описания, советы |
| Логика этапов чек-листа (какой этап активен по дате) | Тексты пунктов чек-листа, источники, критичность |
| Роутинг, рендеринг экранов | Тексты карточек Справки |
| Работа с `localStorage` | Справочники районов/категорий/тегов (`config.json`) |
| Форматирование расстояния («менее 0,1 км» / «~3,4 км» / «~27 км») и выбор точки отсчёта (`resolveOrigin()`) | Подписи для интерфейса, завязанные на контент; ориентиры районов (`spots`) |

Правило: если это придётся редактировать вам лично после запуска без участия разработки — это JSON, а не код.

### B. Final Data Model
`config.json`, `places.json`, `checklist.json`, `info.json` — без изменений относительно `PRODUCT.md` 9.2–9.6. `localStorage` — 4 ключа, без изменений относительно 9.7. *С Итерации 3: `config.areas[].spots` и `stg:trip.stay` (оба необязательны).*

### C. User flows
7 сценариев в разделе 9 — покрывают все Must have функции MVP.

### D. Technical boundaries — что входит в первую кодинг-итерацию

**Входит в первый кодовый шаг (локально, решение №5):** структура проекта, hash-роутинг, нижняя навигация, вкладка «Подготовка» полностью рабочая (аккордеон, чекбоксы, сохранение в `localStorage`), проверка через Live Server — в браузере на десктопе и на реальном телефоне через локальный Wi-Fi.

**Входит во второй чекпойнт Итерации 1 (после первого):** вкладка «Справка», публикация на GitHub Pages, повторная проверка по ссылке с телефона — этим Итерация 1 закрывается по DoD 10.6 `PRODUCT.md` без изменений в его содержании.

**Не входит в Итерацию 1:** «Места», карточка места, «Показать таксисту», Главная «Сейчас» с состояниями по датам, PWA/офлайн — следующие итерации по roadmap, порядок не меняется.
