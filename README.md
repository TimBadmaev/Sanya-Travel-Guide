# Sanya Travel Guide (Sanya Guide)

Карманный помощник туриста из России в Санье. Статический сайт: HTML + CSS +
JavaScript (ES-модули), без сборки и внешних зависимостей. С Итерации 5 —
PWA: устанавливается на экран «Домой» и работает без интернета.

## Локальный запуск

Приложение загружает `data/*.json` через `fetch()`, поэтому двойной клик по
`index.html` не сработает (протокол `file://`, D-25 в PRODUCT.md). Нужен
локальный сервер — расширение **Live Server** в VS Code:

1. Открой папку `sanya-travel-guide` в VS Code.
2. Установи расширение **Live Server** (Ritwick Dey), если его ещё нет.
3. Открой `index.html` и нажми **Go Live** (или ПКМ → «Open with Live Server»).
4. Браузер откроется на `http://127.0.0.1:5500` (или похожем адресе).

**Офлайн-кэш при разработке.** На `127.0.0.1` / `localhost` Service Worker
регистрируется и отдаёт файлы из кэша — правки кода после обычной
перезагрузки видны не будут. На время разработки в Chrome включи
DevTools → Application → Service workers → **Bypass for network** (или
**Update on reload**).

### Проверка на телефоне через тот же Wi-Fi

1. Компьютер и телефон — в одной Wi-Fi сети.
2. Узнай IP компьютера (macOS: «Системные настройки» → Wi-Fi → «Подробнее»;
   Windows: `ipconfig` → `IPv4-адрес`).
3. На телефоне открой `http://<IP>:5500`.

По адресу `http://192.168.x.x` браузер не считает страницу защищённой:
офлайн-режим и подсказка установки там **не включаются**, приложение
работает как обычный сайт. Офлайн на телефоне проверяется только по
опубликованной HTTPS-ссылке.

## Публикация на GitHub Pages

Все пути в проекте относительные — приложение работает из подпапки
`https://<аккаунт>.github.io/<репозиторий>/`.

1. Создай репозиторий на GitHub и загрузи в него содержимое папки проекта
   (файлы `index.html`, `sw.js`, `manifest.webmanifest`, `.nojekyll` должны
   лежать в корне репозитория).
2. Выбери способ публикации — **A** или **B** (ниже).
3. Через 1–2 минуты сайт откроется по адресу
   `https://<аккаунт>.github.io/<репозиторий>/`.
4. Открой ссылку на iPhone в Safari → «Поделиться» → «На экран „Домой“».

### Что именно становится публичным

Важно понимать до первой публикации: GitHub Pages отдаёт **ровно то, что
попало в каталог публикации**, — никакой фильтрации по `.gitignore` там нет.

**Вариант A — «Deploy from a branch» (просто, но публикует всё).**
Settings → **Pages** → Source: **Deploy from a branch**, Branch: `main`,
папка `/ (root)` → **Save**. Публикуется весь репозиторий: приложение плюс
все внутренние документы `*.md`, `yalongwan-plan.html` (личный план поездки
с бюджетами), `tools/` и всё остальное, что лежит в корне. Файлы не
индексируются как страницы, но открываются по прямой ссылке любым, кто её
знает. Секретов в репозитории нет, но личные данные — есть.

**Вариант B — «GitHub Actions» (публикуется только приложение).**
Settings → **Pages** → Source: **GitHub Actions**. Workflow
`.github/workflows/pages.yml` автоматически запускается после каждого
push или merge в ветку `main`; ручной запуск в Actions также сохранён.
Он публикует только `index.html`, `manifest.webmanifest`, `sw.js`,
`.nojekyll`, `css/`, `js/`, `data/`, `assets/`.
Внутренние документы остаются в репозитории, но не входят в сайт.
**Важно:** источник Pages в Settings должен быть `GitHub Actions` —
если выбран `Deploy from a branch`, один лишь запуск workflow не
гарантирует размещения артефакта.

Отдельно: локальные файлы редактора и инструментов (`.idea/`, `.claude/`,
`.mcp.json`) перечислены в `.gitignore`, но были добавлены в репозиторий
раньше — `.gitignore` их с учёта не снимает. Один раз:

```
git rm -r --cached .idea .claude .mcp.json
```

## Как выпустить новую версию

При каждом обновлении меняйте CACHE_VERSION в sw.js и публикуйте новую версию.

1. Внеси правки (код, `data/*.json`, стили).
2. Если добавлен **новый файл**, нужный приложению (js, css, json, иконка), —
   впиши его в массив `PRECACHE` в `sw.js`. Иначе без интернета он не
   загрузится.
3. В начале `sw.js` поменяй значение, например
   `const CACHE_VERSION = "v5-1";` → `const CACHE_VERSION = "v5-2";`.
4. Загрузи изменения в репозиторий (commit + push).
5. Проверка: открой приложение с интернетом — внизу появится плашка
   «Доступна новая версия» → «Обновить». Номер версии виден внизу «Справки».

Без смены `CACHE_VERSION` пользователи продолжат видеть старую версию из
кэша. Отметки чек-листа, избранное и настройки поездки хранятся отдельно
(`localStorage`) и при обновлении не теряются.

Данные пользователя (расходы, план, отметки, избранное, паспорт исследователя, даты) живут только в
браузере телефона. Копию одним JSON-файлом и восстановление из неё даёт экран
«Мои данные» (`#/data`, вход — внизу «Настроек поездки»).

## Проверки

`tests/run_tests.py` — автоматические проверки в настоящем headless Chrome
(Python 3, только стандартная библиотека; Node не нужен): данные и `PRECACHE`,
логика паспорта через `import()`, сценарии экранов, схема побережья и альбом, регрессия всех маршрутов
на 320/375 px, прилёт и первый вечер, фразы и справка для поездки (раздел `travel`), каталог на первом экране, редактор заметки, возврат в контекст, адрес маршрута Amap, поиск из паспорта и справка по группам (раздел `ux`), блок «Начните своё путешествие» на «Сейчас» и хроника паспорта «Мой путь по Санье» (раздел `journey`), офлайн и обновление
установленной версии из `HEAD` до рабочей копии. Раздел `static` заодно проверяет схемы `phrases.json`,
`contacts.json`, `info.json` и `checklist.json` — после правки контента достаточно запустить его. Запуск из корня проекта:

```
python3 -u tests/run_tests.py            # все разделы
python3 -u tests/run_tests.py static unit  # выборочно
```

Нужен Google Chrome (другой путь — переменная `CHROME`). Каталог `tests/` в
приложение и в публикацию (вариант B) не входит. Реальные iPhone и Android
эти проверки не заменяют.

Офлайн-атлас `#/island` основан на данных Natural Earth 1:50m и не требует сетевых тайлов; игровая схема паспорта не изменена. Тёмно-синяя цветовая тема настроена в `css/island.css`.

## Версия v35 — подробная офлайн-карта без лишнего трафика

Карта #/map теперь состоит из двух уровней:

- **Базовый:** настоящие дороги OSM (около 284 КБ JSON) в обязательном PWA precache. Доступны сразу после подготовки приложения к офлайну.
- **Дополнительный, по согласию:** пять независимых файлов data/sanya-detail-{yalong,city,dadonghai,haitang,tianya}.json с реальными OSM-полигонами парков, пляжей, водоёмов и контурами зданий. Районы можно сохранить по одному или все сразу. Общий объём файлов ≈1,5 МБ JSON. До нажатия «Скачать» эти файлы не загружаются по сети.

Кэш детальных районов sanya-detail-v35 хранится отдельно от основного PWA; обычное обновление приложения его не удаляет. Сохранившийся пакет можно использовать в авиарежиме после перезапуска приложения. Устройство может удалить Cache Storage автоматически при нехватке памяти; поэтому перед поездкой нужно **проверить офлайн на реальном телефоне**. Кнопка «Удалить сохранённую детализацию» очищает только дополнительные районы, не затрагивая базовые дороги и пользовательские данные.

Карта показывает масштаб, пять быстрых переключателей районов, обозначения объектов и поддерживает pinch-to-zoom. Онлайн-тайлы по-прежнему требуют явного нажатия; при перемещении уже загруженные видимые тайлы переиспользуются, а не создаются заново при каждом движении. Маршрутизация остаётся внешней (Amap/Яндекс): локальные векторные данные не являются полным дорожным графом и не гарантируют точности маршрутов в КНР. Это **лёгкий собственный Canvas-рендерер**, а не MapLibre/PMTiles: выбор сохраняет простой офлайн-PWA без добавления тяжёлой библиотеки перед поездкой.

Исходный генератор: scripts/build_sanya_roads.py (только настоящие OSM API features, не копирование тайлов). В Actions доступна ручная задача «Build offline Sanya map features (OSM ODbL)». Пять JSON-файлов должны находиться в опубликованном data/, но **не** в списке PRECACHE в sw.js. Публикация через workflow pages.yml копирует всю папку data/.

Проверки: node --experimental-default-type=module --test tests/test_map_routes.mjs и python3 -u tests/test_real_map_browser.py. Требуется тестирование на настоящем iPhone: выключить Wi-Fi/сотовые данные, закрыть PWA, открыть снова, переключить районы, приближать двумя пальцами и проверить, что загрузки не нужны.


## Версия v36 — помощник в поездке и офлайн-мини-игры

**Главная:** контекстная панель с быстрыми действиями перед поездкой, во время отдыха и после завершения. До поездки выделены офлайн-проверка, чек-лист и скачивание аудио; в поездке — план дня, кафе рядом, китайские фразы, адрес отеля, карта и игры. Если адрес отеля не указан, кнопка ведёт в настройки, а не в пустой экран. Существующий игровой путь XP сохранён ниже панели.

**Готовность к офлайну** (адрес #/offline): показывает подтверждённый Service Worker cache, сколько аудиозаписей реально сохранено, какие из пяти районов карты доступны из отдельного кэша, указан ли китайский адрес отеля. Проверка не скачивает файлы автоматически. Ссылки ведут к уже существующим экранам загрузки. Для надёжной проверки перезапустите PWA в авиарежиме. Наличие локальных файлов не делает внешние карты Amap и онлайн-ссылки офлайновыми.

**Игровая бухта** (адрес #/games): три автономные игры на HTML/CSS/JS без новых зависимостей:
- Морской бой 8×8: флот 4/3/2/2 без соприкосновений, случайная расстановка, компьютерный соперник или двое по очереди на одном телефоне. В режиме «вдвоём» перед каждым ходом выводится закрытый экран передачи телефона. Партия переживает перезапуск PWA.
- Китайский экспресс: 10 случайных вопросов из проверенного разговорника. Правильный перевод и пиньинь отображаются после ответа.
- Тропическое мемори: 8 пар, попытки и лучший результат.

Результаты и активная партия хранятся в stg:games. Они включены в резервную копию пользователя и очищаются общим подтверждённым сбросом прогресса. За игры не начисляется XP, чтобы не мотивировать искусственно увеличивать счёт. **Bluetooth и WebRTC между двумя телефонами в v36 не добавлены**: браузерный Bluetooth на iPhone недоступен, а локальный WebRTC требует отдельного тестирования на реальных устройствах. Надёжный офлайн-мультиплеер сейчас — передача одного телефона между игроками.

Проверки:
```bash
node --experimental-default-type=module --test tests/test_minigames.mjs
python3 -u tests/test_games_browser.py
```
Их также запускает pull-request workflow Quality. Все новые JS-файлы находятся в обязательном PWA precache; аудио и детальные карты по-прежнему загружаются только по явному согласию.

## v38 — природная карта, плавная рыбка и два игровых режима для двоих

**Обзор острова:** реальный контур Natural Earth 1:50m, градусная сетка, Хайкоу, компас и возможность убрать точки с карты. Генератор scripts/build_hainan_relief.py получает природные цвета суши и затенённый рельеф из Natural Earth I: https://www.naturalearthdata.com/downloads/10m-raster-data/10m-natural-earth-1/ . Источник является общественным достоянием. Бирюзовая подсветка берегов декоративная, не измеренная глубина моря. Файл WebP остаётся географически выровненным и локальным, без запросов к картографическим серверам.

**Рыбка-поглотитель:** вместо дискретных 50-мс обновлений используется requestAnimationFrame; плавное ускорение и мягкая остановка рядом с указателем; удержание стрелок; более точные короткие нажатия; размеры рыб зависят от текущего размера игрока, без случайного скачка сложности. Пауза при скрытии приложения.

**Две игры на двоих на одном телефоне:** «Четыре в ряд» (чередование ходов, сохранение партии) и «Аэрохоккей» (две независимые клюшки и два одновременных касания). Обе работают полностью офлайн. «Змейка», «Рыбка» и «Тропическое мемори» остаются. Игровые результаты включены в пользовательскую резервную копию.

## Версия v39 — «Моя поездка»: перелёты, отель, документы и быстрые действия

Страница `#/my-trip` открывается с Главной и из «Моего острова». Все поля пустые до ручного ввода пользователя — приложение **не придумывает номера рейсов, города пересадок, терминалы, отель, контактные данные и время вылета**.

- **Перелёты:** по шесть участков «туда» и «обратно»; отдельные аэропорты, локальные даты и часы, рейс, авиакомпания, терминалы, код бронирования, заметка. При изменении поля запись автоматически сохраняется на устройстве. Порядок участков сохраняется в порядке их добавления. Можно удалить участок с подтверждением и скопировать краткий маршрут без кодов бронирований.
- **Отель:** китайский адрес берётся из `stg:trip.home` (прежние настройки, без дублирования); по кнопке открывается большой экран для таксиста. Отдельно сохраняются название, даты заселения/выезда, телефон, email, код бронирования, телефон и email принимающей стороны. Проверенные телефонные номера и почта становятся ссылками.
- **Документы:** восемь практических категорий. Отметки «Есть офлайн» и «Распечатано» заполняются вручную; сами сканы, PDF, паспортные данные, файлы из приложения «Файлы» и банковские реквизиты **не загружаются в приложение**. Отметка не подтверждает наличие файла.
- **Быстрые действия:** показать китайский адрес таксисту, китайский разговорник, офлайн-карта, экстренная справка, проверка кэша, расходы, план прогулок и резервное копирование.
- **Безопасность и офлайн:** `stg:travelcenter` — новый самостоятельный ключ, включён в общий экспорт/импорт, откат после импорта и подтверждённый сброс. В JSON-бэкап могут попасть необязательные коды бронирований и контакты — файл хранить приватно, не загружать на публичный GitHub Pages. Приложение сохраняет данные в localStorage браузера: на чужом телефоне их можно увидеть, а iOS может очистить хранилище. Нет интернет-проверки актуальности рейсов и транзитных правил. Указанные даты и часы не пересчитываются по часовым поясам: перед вылетом всё нужно сверять с перевозчиком.
- **PWA:** новый экран и логика включены в `sanya-guide-v39` precache. Для него не добавлены внешние JS/CSS-библиотеки и автоматическая загрузка документов.

Тесты: `node --experimental-default-type=module --test tests/test_travel_center.mjs` и `python3 -u tests/test_travel_center_browser.py`, встроены в GitHub Actions quality workflow.


## v40 — Travel Assistant: поиск, быстрые действия и первые 24 часа

Сохранена архитектура offline-first без сторонних сервисов поиска и регистрации.

- **Универсальный поиск** `#/assistant`: один запрос на пяти проверенных каталогах — места (`data/places.json`), еда (`data/food.json`), экскурсии, справочник и китайские фразы. Иероглифы, русский текст, пиньинь, описания, категории и районы участвуют в сопоставлении. Неиндексированные и непроверенные записи не показываются. Результаты ведут к **существующим** карточкам, не дублируют данные. Поиск кафе передаёт название в штатный режим `#/places?mode=food&q=...`. Никакие запросы пользователя не уходят в интернет. Новый вход в поиск из шапки, главной и «Открытий».
- **Быстрые действия:** в `#/assistant` открываются шесть готовых сценариев: адрес отеля для такси (из `stg:trip.home`, без дублирования и геолокации), фразы, контакты, карта, еда, документы и перелёты. Кнопка поиска доступна в шапке обычных экранов, а не внутри полноэкранных фраз.
- **Первые 24 часа в Китае** `#/arrival-24h`: 9 необязательных шагов в четырёх этапах — до вылета, после посадки, дорога к отелю, первый вечер. Официальные источники: National Immigration Administration (онлайн Arrival Card с исключениями, бесплатно) https://en.nia.gov.cn/n147418/n147463/c191530/content.html ; Sanya Tourism Board (такси/DiDi и трансферы) https://www.visitsanya.com/planning/travel-guide/getting-there-around/taxis-ride-hailing-services ; транспорт https://www.visitsanya.com/planning/travel-guide/getting-there-around/public-transportation . Информация носит справочный характер: правила въезда, багаж, расписание рейсов, стоимость и посадка в транспорт могут измениться. Нельзя автоматически отмечать выполненные пункты и притворяться, что разрешение на въезд получено.
- **Два телефона:** памятка объясняет самостоятельное скачивание контента и проверку авиарежима на *каждом* устройстве. Приложение не утверждает, что синхронизирует данные между телефонами, не запускает передачу личных документов по Bluetooth и не делает фоновых подключений. Для переноса прогресса используй существующую резервную копию `#/data` (хранить приватно).
- **Китайские фразы:** полноэкранная карточка предлагает воспроизведение **только когда браузер сообщает о локально установленном китайском голосе** `SpeechSynthesisVoice.localService === true`. В противном случае кнопка недоступна с ясным объяснением. Это не гарантированная запись звука и не сетевой TTS — крупные иероглифы и копирование продолжают работать офлайн.
- **Сохранение:** ключ `stg:arrival` нормализован, включён в общий бэкап, безопасное восстановление и подтверждённый сброс. Откаты к копиям v39 и раньше не удаляют новый раздел. Старые данные о билетах, отеле, планах, финансах и достижениях не меняются.
- **PWA:** кэш v40 включает `js/logic/search.js`, `js/views/assistant.js`, `js/logic/arrival.js`, `js/views/arrival.js`. Новые файлы не требуют сетевых сервисов при запуске. После обновления на устройстве проверь актуальность кэша и офлайн-режим.

Проверки: `node --experimental-default-type=module --test tests/test_travel_assistant.mjs` и `python3 -u tests/test_travel_assistant_browser.py` плюс весь старый CI (320px, авиарежим, паспорт, карты, аудио, бэкап, обновление PWA).
