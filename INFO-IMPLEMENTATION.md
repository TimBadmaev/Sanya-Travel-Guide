# INFO — Implementation Specification

> Технический контракт для реализации 4B (вкладка «Справка»).
> Источники: `PRODUCT.md` v1.1, `MVP-UX-SPEC.md`, `CONTENT-INFO.md` v1.0, договорённости Chat 4.
> Версия: **1.0** · Дата: **2026-09-11**

---

## 1. Scope

- Наполнение и подключение раздела «Справка»: список `#/info` + детальный экран `#/info/<id>` для пяти утверждённых тем.
- Новый файл `data/info.json` с пятью записями, контент — дословно из `CONTENT-INFO.md` (без новых фактов, без перефразирования).
- Доработка `js/data.js` — загрузка `info.json` (аналогично существующей загрузке `checklist.json`).
- Доработка `js/app.js` — маршрут `#/info/<id>` (сейчас `#/info` существует только как верхнеуровневый маршрут).
- Новый/дополненный `js/views/info.js` — рендер списка и деталей.
- Доработка `css/styles.css` — стили карточек списка и экрана деталей.
- Состояние пользователя (`localStorage`) для «Справки» не требуется — экраны только читают контент.

---

## 2. Routes

| Маршрут | Поведение |
|---|---|
| `#/info` | Список пяти карточек справки (уже существует как верхнеуровневый маршрут — подключить рендер) |
| `#/info/<id>` | Новый маршрут. Детальный экран одной темы. `<id>` — одно из пяти значений из раздела 3 |
| `#/info/<неизвестный id>` | Запись не найдена или не `verified` → редирект на `#/info` (по аналогии с поведением остальных вложенных экранов при отсутствующей записи) |

Переходы вперёд/назад через `#`-роутинг и кнопку «Назад» браузера работают штатно за счёт существующей архитектуры (D-24) — отдельная логика истории не требуется.

## 3. Content

Порядок и `id` фиксированы, менять нельзя (источник — `PRODUCT.md` 8.8, воспроизведён в `MVP-UX-SPEC.md` §7 и `CONTENT-INFO.md`):

1. `payment` — Оплата
2. `connectivity` — Связь и интернет
3. `taxi-amap` — Передвижение: такси и Amap
4. `emergency` — Экстренные номера и помощь
5. `climate` — Сезон и климат

Шестой темы нет и не добавляется.

**Важное уточнение по маппингу контента** (устраняет потенциальную неоднозначность): в `CONTENT-INFO.md` у каждой темы два разных списка — «Пользовательский текст → Points» и отдельно «Практические действия перед поездкой». В `points` записи `info.json` идёт **только** первый список («Пользовательский текст → Points», 7 пунктов на тему). Раздел «Практические действия перед поездкой» — это редакционные заметки для поддержки контента, в интерфейс пользователя не выводится и в JSON не переносится (схема `info.json`, см. §4, не предусматривает для этого отдельного поля).

## 4. Data schema

Точно по `PRODUCT.md` 9.6, без изменений:

```json
{
  "id": "string, kebab-case, уникальный",
  "status": "draft | verified",
  "title": "string",
  "summary": "string — одна фраза",
  "points": ["string", "... 3–7 штук"],
  "volatile": true,
  "sources": [{ "title": "string", "url": "string" }],
  "verifiedAt": "YYYY-MM-DD"
}
```

- Никаких дополнительных полей (`icon`, `topic`, `order` и т.п. в JSON не добавляются — см. §9 про иконки).
- Показываются пользователю только записи со `status: "verified"` (правило D-18, единое для всего приложения).
- Все пять начальных записей публикуются сразу со `status: "verified"`.
- У всех пяти записей `volatile: true` (по данным исследования 4A все пять тем — изменчивые).

## 5. List screen (`#/info`)

- Рендерит ровно 5 карточек в фиксированном порядке из §3.
- Карточка: иконка (см. §9) + заголовок (`title`) + одна фраза (`summary`). Больше ничего — ни `points`, ни `sources` на списке не показываются.
- Тап по карточке → переход на `#/info/<id>`.
- Без фильтров, без поиска, без счётчика «Найдено N» (это специфика вкладки «Места», сюда не переносится).
- Записи со `status: "draft"` из рендера исключаются (сейчас неприменимо — все 5 verified, но правило действует на будущее).

---

## 6. Detail screen (`#/info/<id>`)

Порядок блоков (по `MVP-UX-SPEC.md` §7 и исходной спецификации Chat 4):

1. Заголовок (`title`)
2. Краткое резюме (`summary`)
3. 3–7 практических пунктов (`points`)
4. Пометка «Может измениться» — показывается только если `volatile === true`
5. Источники (`sources`) — список, каждый источник кликабелен (`title` как текст ссылки → `url`)
6. Дата проверки (`verifiedAt`) — допустимо человекочитаемое отображение (например, «Проверено: сентябрь 2026»); хранимый формат `YYYY-MM-DD` не меняется
7. Элемент «Назад» — возврат на `#/info`

Больше ничего на экране не показывается (без «Практических действий перед поездкой» — см. уточнение в §3).

---

## 7. Navigation

- Нижняя навигация (4 вкладки) остаётся видимой и рабочей на `#/info` и на `#/info/<id>`. Полноэкранный режим без нижней навигации — паттерн, зарезервированный только для будущего экрана «Показать таксисту» (`MVP-UX-SPEC.md` §5); на «Справку» он не переносится, ни один документ этого не требует.
- Элемент «Назад» на детальном экране ведёт конкретно на `#/info` (не просто `history.back()`), при этом штатная кнопка «Назад» браузера тоже должна корректно работать через hash-историю.
- Маршрут `#/info/<id>` реализуется по тому же принципу, что уже используется для `#/place/<id>` в таблице маршрутов — переиспользовать существующий паттерн роутинга, не изобретать новый.

## 8. UX requirements

- Зона нажатия — не меньше 44×44px (карточки, элемент «Назад», ссылки на источники) — D-08.9.
- Основной текст — не меньше 16px, хорошая контрастность — 8.9.
- Никакого горизонтального скролла страницы — `MVP-UX-SPEC.md` §13.
- Только вертикальный скролл, без вложенных скролл-контейнеров.
- Китайский текст — неприменимо (в контенте «Справки» его нет).
- Визуальный стиль (карточки, отступы, типографика) — переиспользует существующие паттерны `css/styles.css` и уже реализованной вкладки «Подготовка»; новая дизайн-система не вводится.

---

## 9. Architecture

**Использовать существующее:**
- `js/app.js` — расширить роутинг маршрутом `#/info/<id>`.
- `js/data.js` — расширить загрузкой `data/info.json`, по аналогии с `checklist.json`.
- `js/views/info.js` — новый/дополненный модуль рендера списка и деталей.
- `css/styles.css` — расширить, переиспользуя существующие классы и паттерны где возможно.

**Не трогать без крайней необходимости:**
- `js/storage.js` — для «Справки» не нужно ни одного ключа `stg:*`, состояние не хранится.
- `js/views/prepare.js` — зависимости между «Подготовкой» и «Справкой» нет, изменения не требуются.

**Решение по иконкам (устраняет неоднозначность из UX-спеки):** `MVP-UX-SPEC.md` требует иконку на каждой карточке списка, но схема `data/info.json` (§4, `PRODUCT.md` 9.6) поля `icon` не содержит и не расширяется. Минимальное решение, совместимое с текущей архитектурой: соответствие `id → иконка` задаётся статическим объектом прямо в коде `js/views/info.js` для пяти фиксированных `id` из §3 — не в JSON-данных. Это сохраняет разделение контента и кода (D-17), так как здесь иконка — не редактируемый контент, а деталь отображения для заранее известного, фиксированного набора из 5 записей. Конкретный визуальный источник иконки (эмодзи, инлайн-SVG, файл из `assets/icons/`) — на усмотрение разработчика, спецификацией не фиксируется.

**Прочее:** без новых зависимостей, фреймворков, CDN, внешних сервисов (D-23, D-28) — scope 4B их не затрагивает. Только ES-модули, без сборки.

## 10. Validation

**Навигация**
- [ ] `#/info` открывается с нижней навигацией, показывает ровно 5 карточек в заданном порядке
- [ ] Тап по карточке → `#/info/<id>` с корректным контентом
- [ ] Элемент «Назад» на детальном экране возвращает на `#/info`
- [ ] Кнопка «Назад» браузера корректно работает на обоих экранах
- [ ] Нижняя навигация видима и рабочая на `#/info` и `#/info/<id>`

**Данные**
- [ ] `data/info.json` успешно загружается через `js/data.js`
- [ ] Показываются только записи со `status: "verified"` (проверить на тестовой draft-записи)
- [ ] Все 5 записей корректно отображают `title`, `summary`, `points`, `sources`, `verifiedAt`
- [ ] Пометка «Может измениться» показывается только при `volatile: true`
- [ ] Ссылки `sources` кликабельны и ведут на правильные URL

**UX**
- [ ] Карточки и текст читаемы на мобильном экране, без горизонтального скролла
- [ ] Touch targets ≥ 44×44px
- [ ] Детальный экран не перегружен, соответствует порядку блоков из §6

**Регрессия**
- [ ] Вкладка «Подготовка» продолжает работать без изменений (чекбоксы, прогресс, аккордеон, `localStorage`)
- [ ] Ключи `stg:*` не затронуты
- [ ] Нет ошибок в консоли браузера
- [ ] Работает в Safari (iOS), Chrome (Android), Яндекс Браузер (D-31)

## 11. Out of scope

- Публикация на GitHub Pages — отдельный следующий шаг, явно исключён из этой итерации.
- Любые темы «Справки» сверх утверждённых пяти.
- Поиск или фильтрация карточек «Справки».
- Новые поля в схеме `data/info.json` (`icon`, `topic` и т.п.).
- Изменение `PRODUCT.md` — расхождения зафиксированы в `CONTENT-INFO.md` §8 и ждут решения владельца отдельно, в 4B не вносятся.
- Изменение вкладки «Подготовка» (`js/views/prepare.js`, `js/storage.js`) без крайней необходимости.
- Офлайн-режим / Service Worker (Итерация 4, D-29).
- Кнопка «Открыть в Amap» / deep-link (Q-03 остаётся открытым).
